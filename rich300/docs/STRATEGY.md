# 추천 전략 자동 추적 (COIN RADAR → RICH300)

사용자가 Binance 에서 매매한 뒤 웹앱에 수동 등록하지 않아도, **추천 → 전략 생성 → Telegram 안내 → 종료까지 가상 추적**이 자동으로 이어진다. 자동 주문은 없다.

## 1. 기존 흐름과 끊겨 있던 원인
1. GitHub Actions `radar` → `signalStep`(RADAR_SIGNAL=on)이 15분봉 확정 트리거로 `CANDIDATE` 를 판정 → `candidateMessage`(+분할 계획 `scaleDecorate`) → Telegram 전송.
2. `RADAR_RICH300_BUTTONS=on` 이면 메시지에 `[진입했어][관망했어][놓쳤어]` 버튼과 `R9 v1 …` 기계 줄만 붙는다. **radar 는 RICH300 으로 아무것도 보내지 않는다.**
3. RICH300 은 사용자가 버튼을 누르고 Telegram 폴링 트리거(`rich300TgPoll`, 운영 승인 필요)가 돌 때만 그 줄을 읽어 신호를 저장했다 → 폴링 트리거·승인이 없으면 추천이 RICH300 에 도달하지 않았다.
4. 설계에 있던 HMAC `doPost`(R5)는 radar 가 호출하는 코드가 연결된 적이 없고(`ingest-client.mjs`는 미사용), 지금 웹앱은 접근 "나만"이라 Actions 의 익명 POST 가 닿을 수도 없다.
5. 이후 RICH300 의 감시(`rich300WatchTick`)는 `Fills`/`ManualPositions` 의 **실제 체결**만 감시했다.

## 2. 새 구조
```
radar(main, 정기/수동 once 실행) 후보 알림 전달 *확인* ─▶ state.signal.feed ─▶ 이 실행의 artifact(rich300-feed-raw, 서명 전·Secret 없음)
rich300-feed.yml(workflow_run: 성공한 main radar 실행) ─▶ 그 실행의 artifact 만 내려받기 ─▶ 실행 id·브랜치·이벤트·신선도 확인 ─▶ HMAC 서명 ─▶ rich300-feed 브랜치 feed.json
RICH300 5분 트리거(rich300WatchTick) ─▶ 피드 가져오기(GET) ─▶ 서명·출처·신선도·되돌림 검증 ─▶ 전략 생성(Strategies 시트) ─▶ 가상 추적 ─▶ Telegram
```
- **서명 필수(fail-closed)**: `RICH300_FEED_KEY`(32자 이상)가 Script Properties 에 없거나 짧으면 피드를 무조건 거부한다. 서명 누락·불일치·변조, 출처(meta: main · once · schedule/workflow_dispatch) 불일치, 게시 또는 radar 산출물이 30분 넘음(stale), 이미 받은 것보다 오래된 ts(replay)도 거부한다. 거부되면 **전략 생성도 Telegram 알림도 없다**(오류 코드만 `strategy:last`에 기록). 이미 만든 전략의 가상 추적과 실제 보유 포지션 감시는 영향받지 않는다.
- **전달 확인된 추천만**: radar 의 Telegram 전송이 성공으로 *확인된* 후보만 피드에 들어간다. 두 번 시도해도 확정되지 않아 '전달된 것으로 간주'한 경우와 전송 실패는 제외된다(자동 추적 대상 아님). 전략 ID 는 radar 신호 ID 와 같아 중복 생성되지 않는다.
- **임의의 캐시를 읽지 않는다**: 게시 워크플로는 `workflow_run` 으로 *성공한 main 정기/수동 radar 실행* 하나가 만든 artifact 만 받는다(실행 id 일치 확인). 실패한 실행·preview·telegram-test·다른 브랜치·push 실행은 artifact 자체가 없거나 조건에서 걸러져 게시되지 않는다. radar.yml 에는 Secret·쓰기 권한이 없다(키와 `contents: write` 는 rich300-feed.yml 에만).
- 지연: 공개 주소 캐시(최대 약 5분) + 5분 트리거 → 추천 후 보통 5~10분. Telegram 메시지에 **COIN RADAR 추천 시각 → RICH300 전달 시각 · 지연 분 · 남은 유효시간**을 표시하고, 10분 미만이면 경고, 이미 지났으면 "실행 불가(전략 만료)" 안내 1건과 기록.
- **관찰 후보 vs 실행 가능 전략**: COIN RADAR 의 후보 알림은 관찰 후보다. RICH300 위험 한도 검증을 통과해야만 "[RICH300 신규 매매 전략] ✅ 실행 가능 전략"으로 안내한다. 통과하지 못하면 "[RICH300 실행 불가] … 관찰 후보일 뿐 진입 추천이 아닙니다"만 보내고 전략으로 만들지 않는다.
- **기존 위치 감시는 그대로**: 같은 5분 트리거 안에서 위치 감시(실제 보유)와 전략 추적이 각자의 설정(`RICH300_WATCH_ALERTS`, `RICH300_STRATEGY`)으로 따로 실행되고, 상태 접두어도 `w:pos:` / `w:sg:` 로 분리된다. 한쪽 실패가 다른 쪽을 막지 않는다.

## 3. 전략 생성 규칙
- 입력(피드): 종목·방향·추천 기준가·최초 손절(시장 구조)·점수·15분봉 시각·유효시간·근거 3줄·거래량·BTC 방향·비용 가정·COIN RADAR 구조 목표(참고)·**구조 정보(1H 지지·저항 구간, 돌파 기준선, 1H ATR)**.
- 평가액 300 USDT 가정, **거래당 위험 1%(점수 80 이상 1.5%)** → 손절가 먼저 → 수량 역산(`scaleplan.mjs`), 격리 3배 이하(청산 여유 부족 시 2배), TP1 +1.5R 50% · TP2 +2R 30% · 잔여 20% 고점−1R 추적(TP1 후 본전). 모든 분할이 체결된 뒤 손절돼도 수수료·슬리피지 포함 손실이 위험 예산 이내인지 검증한다(`risk-over-budget` 이면 제외).
- **분할 진입 가격은 시장 구조에서 찾는다**(`stages.mjs`): 고정 −0.3R/−0.6R 을 쓰지 않는다.
  - 후보: 1H 지지(롱)·저항(숏) 구간 경계, 돌파 기준선 되돌림, 1H·4H·15분 스윙 저점(고점), 1H 20EMA. 가중치 4H 3 · 구간 3 · 1H 2 · 돌파선 2 · 15분 1 · EMA 1, 0.08R 안의 후보는 한 곳으로 합쳐 근거를 모은다. **근거 점수 3 미만은 만들지 않는다.**
  - 지정가는 지지선 바로 위(롱)·저항선 바로 아래(숏)에 둔다(ATR 10% 또는 0.03R 중 큰 값). 검증: 1차에서 0.25 ATR 이상 떨어질 것 · 단계 간격 ≥ max(0.15R, 0.25 ATR) · 손절선에서 0.2R 이상 여유 · 2차 깊이 0.2~0.6R, 3차는 2차+0.15R~0.8R.
  - 2·3차를 함께 놓을 수 있는 조합을 먼저 찾고(근거 점수 합 최대), 없으면 2차까지, 그것도 없으면 **억지로 분할하지 않고 1차 단독**(메시지에 사유 표시). 4시간 추세가 반대면 추가 진입 없음, 1시간 추세가 반대면 2차까지.
  - 시세를 못 받으면 구조 검증을 할 수 없으므로 전략을 만들지 않고 다음 실행으로 미룬다.
- **Telegram 매매 전략 메시지**: 1·2·3차 각각 `가격 / 비중 / 수량 / 증거금`, 산출 근거, 진입 조건·유효기간(2·3차는 신호 후 4시간), 최초 손절가, 1·2차 익절가, 잔여 추적손절, 세 분할 모두 체결 시 평균가, 체결 단계별(1차만·1~2차·1~3차) 평균가와 손절 손실, 전체 예상 최대 손실, 추가 진입 무효화 조건, 추천 유효시간, 시장 구조(15분·1시간·4시간 추세, ATR), 지정가 안내(수량 단위·최소 수량), 가상 체결 주의. 진입·추가 진입·취소 알림에는 *그 시점의* 체결 단계·평균가·손절 시 손실·남은 지정가를 다시 계산해 표시한다. 한 분할이 취소되면 뒤 단계도 함께 취소한다.
- **한도 초과는 일반 추천으로 보내지 않는다**: 일일 가상 손실 −3%(−9 USDT) 도달 · 동시 사용 증거금 30% · 동시 추적 10개 · 계획 불가(최소 주문 단위·비용 과다 등) → `CANCELLED` 로 기록하고 "실행 불가 · 관찰 후보일 뿐 진입 추천이 아닙니다" 안내 1건.

## 4. 상태와 판정 (15분 봉, 보수적)
`CANDIDATE → WAIT_ENTRY → ENTRY_TRIGGERED → TRACKING → TP1 → TP2 → TRAILING`, 종료 `DONE · STOP · INVALIDATED · EXPIRED · CANCELLED`.
- 진입은 사용자의 체결이 아니라 **전략 기준 가상 진입**이며 모든 메시지에 명시한다. 신규 추천 메시지 *이후*에 시작한 봉만 쓴다(지나간 봉으로 체결을 만들지 않음).
- 1차는 지정가(추천 기준가)에 닿을 때 체결. 진입 전 TP1 가격이 먼저 닿으면 `INVALIDATED`(추격 금지), 유효시간이 지나면 `EXPIRED`, 4시간 추세 반전이나 COIN RADAR 의 무효화도 `INVALIDATED`.
- 같은 봉에서 선후를 알 수 없으면 불리한 쪽: 진입 봉에서 손절선까지 내려가면 1·2·3차 모두 체결 뒤 손절 / 손절·익절이 같은 봉이면 손절 / 체결이 일어난 봉의 익절은 인정 안 함 / 본전·추적 손절은 다음 봉부터. 시세 공백은 1시간 봉으로 보충(같은 규칙).
- 알림: 신규 추천 · 진입 구간 접근 · 가상 진입 · 추가 진입/취소 · 손절 접근(시세) · 손절 조건 충족 · TP1/TP2 · 손절 본전 이동 제안 · 트레일링 기준 변경 · 추세 약화(1시간 추세 반대+거래량) · 무효화/만료 · 전략 종료와 최종 가상 성적. 위치 감시와 같은 규칙: 한 번만(전송 전 pending 기록) · 실패는 같은 본문 재시도(2·5·10·20분, 30분 만료) · 시간당 12·일 60건 상한(손절·종료는 예외) · 낡은 시세는 건너뜀.
- 장애 복구: 상태는 Strategies 시트(리비전 이력)와 `w:sg:` 에 있다. 같은 봉을 다시 처리해도 결과가 변하지 않는다(멱등). 전략 ID(`SG-…`)는 radar 의 신호 ID 와 같아 중복 생성되지 않는다.

## 5. 성과 구분
- 추천 전략(가상): `Strategies` 시트 · `?p=strat` 의 "가상 성적". 실제 체결(`Fills`)·수동 포지션(`ManualPositions`)·일지/성적/자산과 **섞지 않는다**.
- 실제 보유 포지션 등록은 선택 기능으로 유지(`?p=pos`).

## 6. main 반영과 켜는 순서 (모두 별도 승인·기본 꺼짐)
`workflow_run` 은 **기본 브랜치(main)에 있는 워크플로 파일**로만 실행되고, 피드는 main 의 `radar.yml` 이 만든다. 따라서 radar 쪽 변경이 main 에 먼저 들어가야 한다. PR #47 은 다른 PR 위에 쌓여 있어(main 대비 26개 커밋) 통째로 병합하면 R9·분할 계획 등 무관한 운영 코드가 같이 들어간다 → **radar 쪽 최소 변경만 담은 별도 브랜치(`feat/rich300-feed-radar`, main 기준)** 를 먼저 반영한다. 파일: `radar-service/signal/{feed,feed-artifact}.mjs`, `step.mjs` 훅, `radar.yml`(변수 1줄 + artifact 2단계), `.github/workflows/rich300-feed.yml`, `rich300/lib/{auth,dedupe,feed}.mjs`, `rich300/client/feed-publish.mjs`, 테스트. 플래그가 꺼져 있으면 radar 동작은 기존과 같다.
순서: ① 최소 브랜치 PR 병합(별도 승인) → ② GitHub 변수 `RADAR_RICH300_FEED=on` + Secret `RICH300_FEED_KEY` → ③ radar 정기 실행 뒤 `rich300-feed` 브랜치·Actions 실행 확인(`workflow_dispatch` 로 radar 를 한 번 수동 실행해 확인 가능) → ④ RICH300 배포(버전 11) → ⑤ `?p=ops` 4번 구역에서 같은 키 저장 → 사전 점검 → `전략 추적 시작`. 중지는 같은 화면의 `전략 추적 중지`.
