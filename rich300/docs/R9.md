# R9 — COIN RADAR ↔ RICH 300 통합

COIN RADAR 추천 → 기존 Telegram 봇 → 사용자 판단(진입/관망/놓침) → 실제 체결 기록 → Google Sheets → RICH 300 웹앱 숫자 화면.
**자동 주문은 없다.** 실제 매수·매도는 사용자가 거래소에서 직접 한다. 별도 테스트 봇은 만들지 않는다(기존 운영 봇 하나).

## 데이터 흐름
```
radar (GitHub Actions)                         RICH 300 (Apps Script, 같은 봇 토큰으로 폴링)
 signal 후보 메시지 ──sendMessage/sendPhoto──▶  Telegram 채팅(사용자)
   + 🆔 고유 ID + 'R9 v1 …' 한 줄                     │ [진입했어] [관망했어] [놓쳤어]  (callback_data = r1:<ID>:e|w|m)
   + 인라인 버튼 3개                                   ▼
                                              rich300TgPoll(1분) ── getUpdates ──▶ 버튼을 누른 메시지의 'R9 v1' 줄을 읽어
                                                   신호 저장(불변) + 응답 저장 → '진입' 이면 입력 화면/명령 안내
                                              입력 화면(?p=fill) 또는 /fill·/exit → 체결 저장(중복 방지) → 장부(R2)
                                              ?p=dash 숫자 화면 · ?p=journal · ?p=signals · ?p=stats · ?p=assets · ?p=check
```
radar → 앱 사이에 **별도 통신·Secret·공개 엔드포인트가 없다.** 신호 상세는 버튼을 누른 메시지 본문에 들어 있고, 앱은 그 메시지에서 읽는다(Telegram이 보장하는 봇 자신의 메시지).

## radar 쪽 변경(기존 운영 영향 없음)
| 항목 | 내용 |
|---|---|
| 플래그 | `RADAR_RICH300_BUTTONS` (저장소 변수, 기본 `off`). `on` 일 때만 진입 후보 메시지에 버튼·ID가 붙는다. |
| off 일 때 | 메시지 본문·전송 인자·재시도·중복 방지 경로가 이전과 동일(테스트로 고정). |
| 대상 | **진입 후보** 메시지(텍스트·사진 모두). 무효화 알림·정기 보고·기회 레이더 메시지는 그대로. |
| 수신 | radar 는 `getUpdates`·웹훅·`answerCallbackQuery` 를 호출하지 않는다(테스트로 고정). |
| 워크플로 | 변수 한 줄만 추가(기본 off). 새 Secret·권한·스케줄 없음. |
| 전략 구분 | 현재 main 의 신호 규칙은 단일 규칙이라 전략 `S`(COIN RADAR 신호). 이중 전략(A/B)이 병합되면 `r9Line(symbol, ev, { strategy })` 로 A/B 를 넘기면 된다(앱은 A·B·S 모두 처리). |

메시지에 추가되는 꼬리: `🆔 SG-ETH-L-xxxxx` + `R9 v1 <ID> <코인USDT> <LONG|SHORT> <진입> <손절> <1차> <2차|-> <전략> <점수|-> <신호시각ms>`.
ID 는 코인·방향·15분봉 트리거 시각으로 결정적이라 재전송돼도 같다.

## 앱 쪽 동작
- **버튼**: 허용된(페어링한) 계정만. 낯선 계정·페어링 전은 무응답·무기록. 같은 버튼을 다시 눌러도 신호·응답은 1건(처음 응답 유지).
- **관망·놓침**: 추천 기록에만 남고 체결이 없으므로 손익·자산에 들어가지 않는다.
- **진입 입력**: 실제 진입가·증거금·레버리지·수량(비우면 증거금×레버리지÷진입가)·손절가(선택)·진입 시각(비우면 지금). 추천가(신호)와 체결가(체결)는 따로 저장.
- **청산 입력**: 실제 청산가·수량 또는 비율(`50%`, `all`)·수수료·펀딩비·청산 시각·복기 메모. 부분 청산을 여러 번 할 수 있고 마지막은 전량.
- **중복 방지**: 폼 id(더블탭·재시도), 체결 id 고정, 같은 계열·가격·수량의 체결이 10분 안에 또 들어오면 거절, 초안 확인(저장) 전에는 기록 없음.
- **손익**: R2(마이크로 USDT, BigInt). LONG/SHORT·체결 수량·입력된 수수료·펀딩 반영. 미입력 수수료·펀딩은 경고로 표시(손익에서 제외, 숨기지 않음).

## 웹앱(숫자 중심, 그래프 없음)
메인(`?p=dash`) 순서: ① 현재 총자산(입력 평가액, 없으면 `미입력`) ② 시작 자금 대비 누적 손익 ③ 누적 수익률 ④ 오늘 시작 자산 ⑤ 오늘 목표 자산 ⑥ 오늘 실현손익 ⑦ 목표까지 남은 금액(초과 시 0 + 달성 표시 별도) ⑧ 날짜별 마감 자산·일간 손익 표.
- 시작 자금 300 USDT, 목표 = 전일 **실제** 마감 자산 × 1.05. 목표치일 뿐 수익을 보장하지 않으며 실제 성과(입력 평가액)와 라벨·줄을 분리해 표시.
- 입출금은 손익·수익률에서 제외(시작 자금 + 순입출금 기준으로 조정).
- 평가액을 한 번도 입력하지 않으면 임의 잔액을 만들지 않는다(`미입력`). 예전 입력만 있으면 입력일을 밝히고 오늘 달성으로 표시하지 않는다.
- 메뉴: 홈 / 일지(진입·청산·복기 메모·날짜·코인 검색) / 추천(추천 신호·응답·실제 매매 여부) / 성적(전략별 승률·누적 손익·평균 이익/손실·손익비·PF·거래 수) / 자산(평가액 입력·입출금·마감 기록·장부 차이).

## 보안 모델
- 웹 앱 배포: **실행 = 접속한 사용자, 접근 = 나만(MYSELF)** → Google 이 소유자 외 접근을 막고, 코드도 `RICH300_OWNER_EMAIL` 과 접속자 이메일을 대조(fail-closed). 이메일을 못 읽거나 다르면 빈 응답.
- 공개 POST 엔드포인트(R5 수신)는 배포상 도달할 수 없다(코드는 남아 있으나 R9 는 쓰지 않음).
- Telegram: 페어링 코드(10분·1회·해시 저장)로 한 계정만 연결. 폴링만 사용(웹훅 없음), 이미 웹훅이 설정된 봇이면 지우지 않고 멈춘다.
- 운영 승인 전(`RICH300_PROD_APPROVED` 없음)에는 Telegram 호출이 0건(코드로 차단).
- 토큰·키·이메일·시트 ID 는 코드·로그·보고서·화면 어디에도 출력되지 않는다.

## 알려진 한계(실환경에서만 확인 가능)
1. Apps Script 폴링은 최소 1분 → 버튼 반응·기록 안내가 최대 약 1분 늦다(`?p=check` 가 실측 평균·최대·간격 이상을 보여 준다).
2. `USER_ACCESSING + MYSELF` 에서 접속자 이메일을 읽는지(안 읽히면 화면이 빈 응답 — fail-closed).
3. Telegram 앱 내장 브라우저가 Google 로그인을 유지하는지(아니면 입력 화면 링크가 로그인을 요구 → `/fill`·`/exit` 명령은 Telegram 안에서 그대로 동작).
4. `drive.file` 권한으로 백업 사본·보관 정리가 되는지, 트리거 실행 시각(마감 00:00~01:00).
5. 실제 신호 메시지에서 버튼·`R9 v1` 줄이 의도대로 오는지(radar `RADAR_SIGNAL=on` 이어야 신호가 전송됨).
