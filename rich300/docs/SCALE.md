# 분할 진입·분할 익절 (안전 중심)

계산·경고·기록만 합니다. **주문 기능은 없습니다.** 실제 주문은 사용자가 거래소에서 직접 합니다. 기본 꺼짐(`RADAR_SCALE_PLAN=off`)이며 운영 배포 전 별도 승인이 필요합니다.

## 기본 규칙 (`radar-service/signal/scale.mjs`, 앱은 `rich300/lib/scaleplan.mjs` 바이트 동일 사본)
| 항목 | 기본값 |
|---|---|
| 진입 비중 | 1차 50% / 2차 30% / 3차 20% |
| 추가 진입 | 1차 진입가에서 손절 쪽으로 0.3R·0.6R의 **사전 지정 가격**에서만. 조건: 직전 15분봉 종가가 구조선(손절+0.25R) 안쪽, TP 체결 전, 신호 후 240분 이내, 단계 순서, 계획 수량 이내, 손절선 안쪽. 손절 만회용 무계획 물타기는 차단(`force=1` 으로만 기록, 요약에 경고) |
| 익절 | TP1 1.5R 50% / TP2 2R 30% / 잔여 20% 추적 손절. TP1 후 손절=평균 진입가(본전), TP2 후 최고가−1R(본전 아래로 내리지 않음). 손절가는 그 전까지 고정 |
| 위험 한도 | 계좌 평가액의 0.5%. **3단계 전부 체결 후 손절**되는 최악(수수료 편도 5bp, 진입 슬리피지 5bp, 손절 슬리피지 10bp 포함)이 한도 이하가 되도록 수량 계산, 수량은 거래소 단위로 **내림** |
| 배율 | 격리 3배 → 청산 여유(손절거리 ≤ 청산거리×0.6) 불충분하면 2배 → 그래도 안 되면 거래 제외 |
| 증거금 | 전체 잔고 사용 금지. 총 증거금 ≤ 평가액의 30%. 메시지에 총 증거금·사용률·유지할 가용 잔고 표시 |
| 소액 계정 | 단계별 수량이 최소 주문 단위 미만이면 3→2→1단계로 축소, 그래도 안 되면 제외. 비용이 R의 35% 초과(손절이 너무 가까움)·증거금 한도로 수량이 계획의 40% 미만이면 제외 |

주문 규격(`step/minQty/minNotional`)은 주요 코인 참고표입니다. 실제 규격은 거래소 화면에서 확인하세요(틀리면 거래소가 거절하므로 안전한 쪽).

## Telegram 신호 (레이더, `RADAR_SCALE_PLAN=on`)
후보 메시지에 각 진입의 가격·비중·수량·증거금·손절 시 손실, 추가 진입 조건, 각 TP 가격·비중, 최악 손실(=평가액 %), 총 증거금·사용률·가용 잔고·청산가(근사)가 붙습니다. 사진 설명에는 3줄 요약. 평가액은 `RADAR_PLAN_EQUITY`(기본 300) **가정값**입니다.

## 앱 (RICH 300)
- [진입했어] 안내에 실제 평가액(오늘 시작 평가액)으로 계산한 계획 카드가 붙습니다.
- 첫 진입 체결 기록 시 계획 **입력**(평가액·진입가·손절·배율·단계)이 `Plans` 시트에 불변으로 1건 저장됩니다. 계획은 이 입력에서 결정적으로 재계산됩니다.
- `/plan 신호ID [평가액]`: 계획 + 현재 상태(단계별 체결·부분 체결, 미체결 추가 주문 유지/취소 안내, TP 체결 후 잔여 수량 = 손절 수량, 손절가 종류, 지금 손절 시 손익, 미체결이 모두 체결될 때 최악).
- `/fill` 추가 진입 검사: 위반 시 사유와 함께 차단. 첫 진입 수량이 계획 1차보다 크면 경고. 평가액이 없으면 계획이 저장되지 않아 추가 진입은 `force=1` 이 필요합니다.
- 구조 유지(직전 15분봉 종가)는 앱이 봉 데이터를 갖고 있지 않아 **직접 확인**해야 합니다.

## 검증
- 단위·속성 테스트: 무작위 3,000건에서 최악 손실 ≤ 한도, 증거금 ≤ 한도, 수량이 단위 배수, 청산 여유 보장.
- 시뮬레이터(`scale-sim.mjs`): 보수적 체결 가정(같은 봉에서 손절·익절이 겹치면 손절 먼저, 추가 체결 직후 손절 가능, 갭 손절은 시가 청산 — 한도 초과로 별도 집계). 변형: 단일 진입, 50/30/20, 40/30/30, 60/25/15, 70/30, 추가 깊이 0.2/0.4·0.4/0.8R, 익절 40/30/30·60/20/20, 본전 이동 유무.
- 합성 경로(`scale-synth.mjs`)는 **메커니즘 검증용**입니다(한도 유지·체결 순서). 예: 눌림형(B형 모양)은 분할이 단일보다 평균 R이 낫고, 추세형(A형 모양)은 분할이 체결률 하락만큼 이익을 줄입니다. 이는 가정한 경로의 성질이지 **성과 증거가 아닙니다**.
- 실데이터: Actions `scale-backtest` (수동 실행, 읽기 전용, 공개 OKX 시세). 전략 `S`(현재 신호 레이더)는 내장. A/B(이중 전략)는 해당 PR 병합 후 `--adapter` 모듈로 연결합니다. 이 개발 환경에서는 OKX 접속이 안 되어 **실데이터 결과는 아직 없습니다**.
- 모의매매: 기존 `RADAR_SIGNAL_PAPER` 기록과 같은 확정 봉에 `scaleSimulate` 를 적용하는 방식으로 확장 가능(이번 PR에는 포함하지 않음).

## 되돌리기
`RADAR_SCALE_PLAN` 변수 삭제 또는 `off` → 레이더 메시지는 이전과 같습니다. 앱 쪽 `plan` 기록은 참고용이라 삭제하지 않아도 동작에 영향이 없습니다.
