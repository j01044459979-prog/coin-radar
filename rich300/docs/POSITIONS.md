# 수동 포지션 등록과 감시 (?p=pos)

Binance 선물에서 직접 연 포지션을 웹앱에 기록하고, 그 **실제 보유 포지션만** 감시 대상으로 쓴다. 주문·계정 API 는 없다(자동 주문 없음).

## 입력 항목
종목(BTC / ETHUSDT / BTC-USDT-SWAP / BTCUSDT.P 모두 가능), LONG/SHORT, 실제 진입가, 수량(또는 증거금 — 하나만 넣으면 나머지는 계산), 레버리지, **손절가(필수)**, 1·2차 익절가(선택), 체결 시각·수수료·펀딩(선택).

- COIN RADAR 추천 여부와 무관하다. 종목은 OKX·Bybit 공개 티커로 확인한다(두 곳 모두 "없음"이면 거부, 응답을 못 받으면 경고만).
- 저장은 체결(`Fills`, origin=real) + 수동 등록 정보(`ManualPositions`: 종목·손절·익절) 두 기록. sid 는 `M-<종목>-<L|S>-<폼 id>`.
- 같은 폼 재제출은 1건. 같은 종목이 이미 보유로 등록돼 있으면 거부(`force` 로만 허용). 동시 보유 10개 상한.
- 규칙(레버리지 3배 초과·손실 1.5% 초과·증거금 30% 초과·청산가가 손절보다 먼저)은 **경고만** 한다 — 이미 체결된 실제 포지션을 기록하기 때문이다.
- 손절·익절 수정: 손절은 좁히기만(넓히기 거부), 익절은 자유. 모든 수정은 이력(Audit)에 남는다. 청산은 `?p=fill&mode=exit&sid=…`(기존 청산 화면).
- 새 시트 `ManualPositions` 가 처음 열 때 자동으로 만들어진다(기존 시트·데이터 불변).

## 감시(5분)와 알림 조건
감시 트리거를 설치하고 `RICH300_WATCH_ALERTS=on` + `RICH300_PROD_APPROVED=yes` 일 때만 전송한다(지금은 모두 꺼짐).

| 알림 | 조건 | 중복 방지 |
|---|---|---|
| 손절 임박 | 시세가 손절까지 0.25R 이내 (0.5R 이상 벌어지면 재무장) | 접근 횟수별 키 |
| 손절 이탈 | 시세가 손절가를 넘음 | 포지션·손절가별 1회 |
| 손절 위험(추세) | 0.6R 이내 + 1시간 추세 반대 + 거래량 1.2배 | 1시간 쿨다운 |
| 익절 도달 | 사용자 지정 1·2차 가격(없으면 +1.5R/+2R) | 단계별 1회, 청산 기록 시 완료 |
| 추적손절 안내 | 1차 청산 뒤 본전, 2차 청산 뒤 고점(저점)−1R. 유리한 방향·0.25R 단위 | 가격별 1회 |
| 스윙 후보/유지/종료 | 수익 포지션만(기존 규칙) | 기존 |

- 1R = 평균 진입가와 **처음 등록한 손절**의 거리(손절을 본전으로 옮겨도 1R 은 유지).
- 시세 지연: 현재가 10분 초과·봉 끊김·가격 불일치면 그 종목은 알림 없이 건너뛴다. 전체 시세 실패가 3회 연속이면 장애 알림 1회, 일부 종목만 3회 연속 실패하면 종목별 알림 1회(복구 시 해제).
- API 장애: OKX 실패 시 Bybit 로 대체. 실행 시간 240초를 넘기면 남은 종목은 다음 실행으로(결과에 `time-budget`).
- 일일 손실 한도(−3%): 오늘 실현+평가 손익이 한도에 닿으면 추가 진입 알림을 막고 하루 1회 알림.
- 전송은 한 번만(`pending` 표시 후 전송), 실패는 같은 본문으로 재시도(2·5·10·20분), 30분 지나면 만료. 시간당 12·일 60건 상한(손절 관련은 예외).

## 실전 감시 활성화에 필요한 조건 (모두 별도 승인)
1. 버전 배포 승인(이 기능 포함 빌드) → 폰에서 `?p=pos` 로 가상이 아닌 실제 포지션 1건 등록(또는 등록 없이 대기).
2. `RICH300_PROD_APPROVED=yes` (Telegram 감시·폴링 메시지 허용).
3. `RICH300_WATCH_ALERTS=preview` 로 `?p=watch&run=1` 미리보기 확인 → 시세 연결 점검(`&net=1`) 정상.
4. `rich300WatchInstallTrigger()` 직접 실행(5분 트리거 1개).
5. `RICH300_WATCH_ALERTS=on`.
