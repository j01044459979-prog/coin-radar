# RICH 300 — R5 API 서명 검증 (오프라인 개발, Apps Script 실제 동작은 S0 전까지 미확정)

`rich300/lib/auth.mjs`(검증) · `rich300/lib/ingest.mjs`(수신 처리) · `rich300/client/ingest-client.mjs`(송신, Node) · `rich300/gas/Api.gs`(Apps Script 진입점, 미배포).

## 요청 형식
`{"v":1,"ts":<ms>,"nonce":"<16~64자 [A-Za-z0-9_-]>","body":{…},"sig":"<hex64>"}` — `sig = HMAC-SHA256(key, "v.ts.nonce.canonical(body)")`, canonical = 키 정렬·공백 없는 JSON. body에는 **부동소수·BigInt·undefined 금지**(금액은 문자열, 정수는 안전 정수만) — 언어 간 정규화 불일치를 구조적으로 차단. 알 수 없는 필드·누락 필드 거부.

## 검증 순서 (값싼 검사 → 서명 → nonce)
형식·크기(8KB)·버전 → 시각(±5분) → 정규화 → **키 후보를 전부 계산해 상수 시간 비교**(현재·이전 키) → 서명이 맞은 요청만 nonce 기록(캐시 오염 방지) → 재사용이면 거부. 키가 없거나 32자 미만이면 **닫힌 채로 실패**.

## 실패 처리와 Secret 비노출
- 외부 응답은 사유와 무관하게 `{"ok":false,"error":"unauthorized"}` 한 가지(형식·시각·서명·재전송·키 미설정 모두 동일). 사유는 내부 카운터(`auth-fail:<사유>`)에만 남는다.
- **시트는 인증 통과 후에만 연다**(위조 요청이 락·시트를 소모하지 못함).
- 키·서명·본문은 반환값·오류·카운터·로그 어디에도 넣지 않는다(테스트가 직렬화 결과를 검사). 코드에 로그 출력 없음, 키는 `PropertiesService`에서만 읽음, 클라이언트 오류는 URL·키를 버리고 코드(`network`/`timeout`/`bad-response`)만 반환.
- 키 회전: `RICH300_INGEST_KEY`(현재) + `RICH300_INGEST_KEY_PREV`(선택). 회전 후 이전 키는 삭제.

## 재전송 방지의 이중 구조
1. nonce 캐시(TTL 15분 > 유효 창 10분): 같은 요청 재전송 거부. **CacheService는 퇴출될 수 있다(최선 노력).**
2. 저장소 유일키(sid): 캐시가 비어 같은 요청이 인증을 다시 통과해도 신호는 `duplicate`로 한 번만 저장(테스트: 캐시 퇴출 후 재전송).
- 클라이언트 재시도는 **새 nonce·시각으로 다시 서명**(같은 nonce 재전송은 거부되므로). 응답이 유실돼도 새 요청이 `duplicate`로 처리되어 정확히 1건만 저장(테스트: 첫 응답 유실).
- 비멱등 작업(R4 텔레그램 버튼)은 nonce가 아니라 `update_id`/`callback_id` 선점(`storeClaimUpdate`)으로 방어한다.

## 검증
테스트 90건(R5 관련 21건): Python `hmac`/`json` 독립 기준값 60건(비ASCII·이모지·중첩·키 정렬)과 정규화 문자열·서명 일치, 변조·형식·시간 경계(±5분 포함/초과)·재전송·캐시 오염·키 회전·키 오설정·카운터·Secret 비노출·소스 위생, 클라이언트→302 응답 서버→핸들러 종단, `Api.gs`를 가짜 Apps Script 서비스에서 실행.

## 미확정 (S0 실측 대상 — 가정으로만 설계)
| 가정 | S0 확인 |
|---|---|
| `doPost`가 헤더를 못 읽음 → 본문 서명 | 헤더 노출 여부 |
| POST 응답이 302로 전달되고 `redirect: follow`로 결과를 읽을 수 있음 | 상태·Location, 본문 수신 |
| `Utilities.computeHmacSha256Signature(message, key)`가 문자열을 **UTF-8**로 처리 → Node와 서명 일치(한글·이모지) | **프로브가 이제 한글·이모지 본문으로 서명 일치(sigOk)를 확인** |
| `CacheService` TTL(최대 6시간)·퇴출 동작 | nonce 동작 |
| 동시 요청 시 락·카운터 | 병렬 8건 |
| 익명 배포의 요청 폭주 내성·실행 시간 | 지연 분포 |
실측 전에는 운영 배포·Secret 등록·GitHub Secret(`RICH300_GAS_URL`, `RICH300_INGEST_KEY`) 설정을 하지 않는다.
