# 실제 환경 검증 — 최종 설치 방법 (사용자 작업 최소판)

이 문서가 `LIVE-TEST.md`의 절차(1·2장)보다 **최신**입니다(설치·검증·요약을 `rich300LiveStart` 한 함수로 통합). 모든 시험은 **테스트 환경**(별도 프로젝트·시트·봇)에서만 하며, 기존 radar·기존 Telegram 봇·운영 Secret·운영 웹앱은 건드리지 않습니다. 테스트 프로젝트·시트·백업·봇은 **결과 확인 전에 삭제하지 않습니다.**

## 사용자가 해야 하는 일 (반드시 사람이 해야 하는 것만)
총 약 25분 + 휴대폰 15분. **로그/스크린샷 요청은 마지막 한 번(최종 결과 메시지)뿐입니다.**

| # | 작업 | 시간 | 왜 사람이 해야 하나 |
|---|---|---|---|
| 1 | Telegram에서 `@BotFather` → `/newbot` → 이름 `RICH300 TEST`, 사용자명은 **반드시 `test`가 들어가게**(예: `rich300_test_ab12_bot`) → 토큰 복사(메모장에만) | 3분 | 봇 토큰 발급은 BotFather만 가능 |
| 2 | script.google.com → **새 프로젝트** → 이름 `RICH300-TEST` (S0 프로젝트와 별개) | 1분 | Google 로그인·프로젝트 생성 |
| 3 | 프로젝트 설정(⚙) → "appsscript.json 매니페스트 파일을 편집기에 표시" 켜기 → 편집기에서 `appsscript.json`, `Code.gs`를 아래 파일로 **전체 교체**하고, 파일 추가(+ → HTML) 이름 `Fill` 에 `Fill.html` 내용 붙여넣기 | 5분 | 코드는 Google 계정 안에서만 반영 가능 |
| 4 | 프로젝트 설정 → 스크립트 속성 → 속성 **1개** 추가: 이름 `RICH300_TG_TOKEN`, 값 = 1번 토큰 | 2분 | 비밀값은 채팅·저장소에 두지 않음 |
| 5 | 배포 → 새 배포 → 유형 *웹 앱* → 실행: **웹 앱에 접속하는 사용자**, 액세스: **Google 계정이 있는 모든 사용자** → 배포 | 3분 | 배포 생성·동의는 사람만 가능. (이 설정이어야 "다른 계정 차단" 시험이 의미 있고, 접근 제어는 코드(소유자 이메일 확인)가 합니다) |
| 6 | 편집기 상단 함수 선택에서 **`rich300LiveStart`** 선택 → ▶ 실행 → 권한 동의("확인되지 않은 앱" → 고급 → 이동 → 허용) → 실행 로그 맨 아래의 **`https://t.me/…?start=…` 링크** 확인 | 5분(실행 1~2분) | OAuth 동의는 자동화 불가 |
| 7 | 휴대폰에서 그 링크 열기 → **시작(START)**(10분 안) → 이후 `[TEST]` 메시지의 버튼만 따라 누르기(약 15분) | 15분 | 실제 Telegram 송수신 시험 |
| 8 | (가능하면) 두 번째 Google 계정 또는 시크릿 창에서 배포 주소를 1회 열어 보기(빈 화면이면 정상) — 불가능하면 건너뛰기(결과에 "미검증"으로 기록) | 2분 | 접근 차단 시험 |
| 9 | 24~30시간 뒤 봇이 보내는 `[TEST] LIVE 최종 결과` 메시지를 **복사(또는 캡처)해 한 번만 붙여 넣기** | 1분 | 결과 판정 전달 |

배포 주소를 속성에 따로 넣을 필요는 없습니다(`rich300LiveStart`가 자동 인식). 인식에 실패하면 웹 단계만 "미검증(SKIP)"으로 기록되고, 그때만 `RICH300_UI_URL`에 배포 주소를 넣고 `rich300LiveStart`를 다시 실행하면 됩니다.

### 파일 (GitHub raw 링크는 보고서에 있음)
`rich300/live-kit/appsscript.json`, `Code.gs`(약 300KB — 전체 선택·복사·붙여넣기), `Fill.html`. 같은 폴더의 `MANIFEST.txt`는 해시 목록(참고용). 생성: `node rich300/deploy/make-bundle.mjs --env test rich300/live-kit` (동기화 시험으로 항상 현재 코드와 같음).

## `rich300LiveStart` 가 자동으로 하는 일 (이후 사용자 입력 없음)
1. **환경 가드**: 운영 환경·운영 승인 플래그가 있으면 즉시 거부. `RICH300_ENV=test` 설정, 소유자 이메일 기록, 테스트 시트 생성·환경 표식, `RICH300_TEST_TG_ALLOW=yes`(테스트 봇 호출 허용).
2. **봇 확인**: `getMe` 로 사용자명에 `test` 가 있는지 확인(운영 봇 토큰을 실수로 넣으면 **거부**, 어떤 메시지도 보내지 않음), 웹훅이 있으면 제거(테스트 봇 한정).
3. **빠른 자동 검증 A·B**(약 20~40초): V8·BigInt·고정소수점·복리·손익·HMAC(한글·이모지) 벡터, 시간대·KST 경계, 자가 점검, 1년 3,285체결 장부 계산 시간, 일지 렌더 시간. **A 실패 시 트리거를 설치하지 않고 중단.**
4. **예산 점검**: 유휴 폴링 5회 실행 시간을 재서 하루 예상 실행 시간을 계산 → 60분 이하면 1분 간격, 아니면 5분 간격, 5분도 안 되면 **설치하지 않음**(`LIVE-QUOTA.md`).
5. **트리거 설치**: 폴링(1분 또는 5분), 일 마감(00시 + 매시간), 주 1회 백업. 시험 상태 초기화.
6. **페어링 링크 출력**(10분 유효, 1회용).
7. **백그라운드(일회성 트리거, 30초 간격으로 구간별)**: C 실제 시트 저장·읽기(100회 저장 p50/p90, 감사 500/2,000/5,000행 전체 읽기, 5천 행에서의 저장 시간, 텍스트 서식 보존·무결성, 중복 키), G 백업·복원 리허설(테스트 시트 백업, 임시 시트로 3회 백업·8개→2개 보관·휴지통 이동, 복원, 변조 탐지, 환경 표식 불일치, Telegram CSV 전송 0건).
8. 페어링되면 **휴대폰 마법사**가 시작: 10단계 안내(버튼 중심)와 **자동 판정**.
9. 15분쯤 뒤 **중간 결과**가, 24시간 뒤 **최종 결과**가 `[TEST]` 메시지(PASS/FAIL/WAIT/WARN/SKIP, 값 없음)로 도착합니다. 시험이 36시간을 넘기면 **자동으로 폴링을 멈추고** 마지막 결과를 보냅니다.

## 휴대폰 시나리오(마법사 10단계, 버튼 위주)
1 [진입했어] 두 번 연타 → 2 [진입 기록 만들기]→[저장] → 3 [같은 입력 다시 만들기]→[저장](거절돼야 정상) → 4 [부분 청산 만들기]→[저장] → 5 웹 입력 화면에서 청산(저장 두 번 눌러 보기) → 6 복기 [저장] → 7 [평가액 입력 만들기]→[저장] → 8 웹 일지에서 체결 수정(사유) → 9 웹 일지에서 입출금 기록 → 10 만료 시험(바로 아래 확인 메시지를 **11분 뒤에** 누르기).
이후 **자정(00:00~01:00 KST)에 일 마감 알림이 1회** `[TEST]`로 올 수 있습니다(테스트 환경 전용 플래그 `RICH300_TEST_CLOSE_SEND`; 운영 알림 승인과 무관).

## 중단·정리
- 언제든 `rich300LiveStop` 실행 = 트리거 제거 + 상태 기록(데이터·시트·백업·봇은 그대로). 자동 중단 조건은 `LIVE-QUOTA.md`.
- 토큰 폐기: BotFather `/revoke`(테스트 봇만).
- 결과 확인 뒤에 **삭제할 것(임시 시트·백업 폴더·테스트 시트·프로젝트)을 목록으로 보여 드리고 확인받은 뒤에만** 지웁니다.

## 문제 해결
| 증상 | 조치 |
|---|---|
| 로그에 `RICH300_TG_TOKEN … 입력` | 4번 속성을 추가하고 `rich300LiveStart` 재실행 |
| `봇 확인 실패(not-test-bot)` | 운영 봇 토큰입니다 — 사용자명에 `test`가 든 **새 봇**을 만들어 토큰 교체(운영 봇에는 아무 메시지도 가지 않음) |
| `token-rejected` | 토큰 오입력/폐기 — 새로 복사 |
| `실행 시간 예산 초과` | 이 계정의 Apps Script가 매우 느립니다 — 결과를 알려 주세요(설계 변경 검토) |
| 페어링 링크가 만료(10분) | `rich300LiveStart` 를 다시 실행하면 새 링크가 로그에 나옵니다 |
