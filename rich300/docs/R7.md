# R7 — 매매일지·10초 복기 분석·일 마감 (오프라인 개발 완료, 운영 배포·실제 알림 없음)

상태: 코드·테스트 완료. **병합·운영 웹앱 배포·실제 Telegram 발송은 하지 않았습니다.** 일 마감 알림은 **기본 OFF**이며 이중 잠금(설정 + 승인 플래그)입니다. 기반: PR #37(R4) 브랜치 위에 쌓인 스택(R4의 `/equity` 명령과 알림 발송을 사용).

## 구성
| 파일 | 역할 |
|---|---|
| `lib/close.mjs` | 일 마감(KST 00:00), 평가액 입력, 마감 알림(1회·기본 OFF), 진단 경고 |
| `lib/analytics.mjs` | 승률·손익비·Profit factor·기대값(USDT·R)·최대 낙폭, A/B·LONG/SHORT·복기 항목별 분석 |
| `lib/journal.mjs` | 일지 조회(체결 타임라인·수정 이력 diff·마감 상태·경고), 체결 수정/취소·입출금 기록(사유 필수, 사전 검증) |
| `lib/journalview.mjs` | 모바일 일지 화면(서버 렌더링, 이스케이프, 수정 폼) |
| `lib/schema.mjs` | 엔티티 `dayclose`(불변), `closenotice`(리비전) 추가 |
| `gas/Journal.gs` | `?p=journal` 페이지, `google.script.run` 서버 함수(각각 소유자 확인), 마감 트리거(00시 + 매시간) |
| `lib/tg.mjs`(R4 확장) | `/equity 금액 [날짜]`, 알림 발송(`tgSendNotice`) |

## 1. 매매일지 조회·수정 이력
- 거래 카드: 방향·종목·전략·진입→청산·순손익·응답(진입/관망/놓침)·복기, 체결 타임라인(가격·수량·수수료·펀딩 상태).
- **수정 이력**: 체결·복기·입출금의 모든 리비전을 Audit에서 읽어 `rev · 시각 · 수정/취소 · 사유 · 필드별 전후 값`으로 표시. 취소된 체결은 별도 목록(손익 제외)과 이력으로 남음.
- **수정**: 허용 항목(가격·수량·시각·증거금·레버리지·계획 손절·수수료·펀딩·메모)만, **사유 필수**. 저장 전에 수정 후에도 거래가 계산되는지 미리 검증(진입을 줄여 청산이 잔량 초과가 되는 수정 등은 거절). 이전 값은 사라지지 않음(추가 전용).
- 입출금 기록은 `cfId`(폼 식별자)로 중복 제출 1건. 취소는 사유 필수.

## 2. 10초 복기 저장·통계 분석
- 저장은 R4(저장 버튼을 눌러야 기록, 기본값 비저장) 그대로. 일지는 복기 수정 이력도 표시.
- 분석: 계획 준수·심리 상태별 거래 수·승률·기대값·순손익, 복기율. **규칙 기반 문장**(예: "계획과 다르게 한 거래의 건당 기대값이 …보다 낮습니다")은 두 집단 모두 5건 이상일 때만 만들고, 30건 미만이면 "참고용"을 붙이며 인과를 주장하지 않음.

## 3. A/B 전략별 분석
승률(+95% Wilson 구간) · 평균 이익/손실 · **손익비**(평균이익÷평균손실) · **Profit factor** · **기대값**(건당 평균 순손익, 계획 손절이 있는 거래는 R-배수와 커버리지) · **최대 낙폭**(청산 순서 누적 손익 곡선, 시작 자금 대비 %) · 최고/최저. 전체·A·B·LONG·SHORT·(전략×방향)을 제공. 표본 30건 미만은 "표본 부족" 표시. 입력은 R2가 계산한 실제 청산 거래의 순손익뿐(모의 제외, 새 손익식 없음). 손계산 값으로 검증.

## 4. 시작 자금 300 USDT·일일 목표 5% 유지
챌린지는 불변(다른 값으로 재생성 시 conflict), 마감 기록의 목표는 R2의 "전일 *실제* 마감 × 1.05, 미달분 비이월"을 그대로 저장. 테스트로 고정.

## 5. 매일 KST 일 마감
- `closeTick`: 00:00 트리거 + 이후 매시간 재확인(Apps Script `atHour(0)`은 00:00~01:00 사이 실행되므로 재확인 필요). 어제까지 아직 마감되지 않은 날을 **날짜 순서대로 한 번씩**(놓친 날 포함, 최대 31일) 마감.
- 마감 기록(`dayclose`)은 마감 시점의 스냅샷: 시작·목표·마감(입력 또는 장부 근사)·손익·장부 잔고·차이·경고 코드. 평가액을 나중에 입력해도 기록은 바뀌지 않고 입력이 "마감 후 입력(late)"으로 표시됨.

## 6~7. 평가액 미입력 알림 1회, 운영 승인 전 OFF
- 조건: 마감된 날에 평가액이 없을 때. 날짜당 **최대 1회**(`closenotice`), 여러 날이 한 번에 마감되면 한 메시지로 묶음. 문구 2줄 + [입력하기] 링크(`?p=journal&day=…#close`). 금액은 장부 잔고만 표시하고 **평가액을 대신 채우거나 추정해 저장하지 않음**.
- **기본 OFF, 이중 잠금**: 설정 `closeNotify=on` **그리고** Script Property `RICH300_CLOSE_SEND_APPROVED=yes` 일 때만 발송. 꺼져 있으면 `closenotice(off)`만 기록해 나중에 켜도 과거 날짜를 소급 발송하지 않음.
- 재시도: 확실한 실패만 총 2회까지. 발송 중 중단(결과 불명, pending 15분 초과)은 `unknown`으로 두고 재발송하지 않음(중복보다 누락을 택함). 평가액을 입력하면 재시도 중단.

## 8. 누락·불일치 경고
수수료·펀딩 미입력, 추정치 포함, 장부-입력 평가액 차이(허용: max(1 USDT, 0.5%)), 평가액 미입력(장부 근사), 미실현 손익 누락, **입출금 누락 의심**(거래·입출금·조정이 없는 날의 큰 차이), **수수료·펀딩 미입력이 원인일 수 있음**. 모두 일지·마감 기록·알림에 표시만 하고 **자동 보정하지 않음**(입출금·조정은 사용자가 기록).

## 9. 동일 일자 중복 마감 방지
날짜가 키인 불변 엔티티 + 스크립트 락. 계획(`closePlan`)과 확정(`closeCommit`)을 분리해, 계획 후 다른 트리거가 먼저 확정해도 한 건만 남음(테스트로 재현). 락 실패는 아무것도 쓰지 않고 다음 실행에서 정상 마감.

## 10. 통합 테스트(R2~R6와 함께)
R2 장부 · R3 저장소/감사/무결성 · R4 Telegram(`/equity`, 퍼징) · R5 서명 수신(기존) · 일지/마감/통계 · Apps Script 환경(가짜 서비스) · Chromium 렌더(390/320px, 폼 인자 전송, 중복 클릭 방지). 병합 시뮬레이션은 `docs/DEPENDENCIES.md`(R8 브랜치) 참고.

## Apps Script 보안 요약
- `?p=journal`은 소유자 이메일 확인 통과 시에만. `google.script.run` 대상 함수는 **각각** 확인(타인·익명 `forbidden`, 시트 미변경 — 테스트).
- 입력 오류는 안내 문구만, 내부 오류는 `server`(스택·ID 비노출). 로그 출력 없음. 외부 호출은 승인된 알림 경로(Telegram)뿐이며 기본 OFF.

## 한계 / 후속
- 알림 실발송은 이 환경에서 검증하지 못했습니다(가짜 Telegram만). 테스트 프로젝트에서의 1회 시험 발송은 별도 승인 필요.
- 트리거 시각 정확도·`atHour(0)` 지연은 S0 `s0Daily` 실측 결과에 의존합니다(현재 `daily=[]`로 미확인).
- 일지는 최근 40건만 표시(1년치 계산은 오프라인 1초 이내). 대용량에서의 Apps Script 실행 시간은 실측 필요.
