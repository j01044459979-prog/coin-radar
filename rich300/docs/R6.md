# R6 — 모바일 대시보드 (오프라인 개발 완료, 운영 배포 없음)

상태: 코드·테스트·화면 검증 완료. **운영 웹앱 배포·실제 데이터 연결·병합은 하지 않았습니다.** 실제 기록이 없으면 샘플 데이터로 화면을 검증합니다(명시 배너, 저장 안 함).

## 구성
| 파일 | 역할 |
|---|---|
| `lib/dashboard.mjs` | 뷰 모델(순수): R2 장부 결과 + 신호·응답·복기 → JSON-안전 표시값. 샘플 데이터 생성 |
| `lib/dashview.mjs` | 서버 측 HTML 렌더(인라인 CSS/JS/SVG, 외부 자원 없음, 모든 값 이스케이프) |
| `gas/Dashboard.gs` | `?p=dash` 페이지 함수(읽기 전용). 라우터(`Api.gs`)가 소유자 이메일 확인(fail-closed)을 통과시킨 경우에만 호출 |
| `docs/img/*.png` | 샘플 데이터 렌더 스크린샷(390px 라이트/다크, 320px) |

## 화면 구성(위에서 아래로)
1. **오늘 카드**: 오늘 시작 평가액 · 목표 마감액(전일 *실제* 마감 × (1+목표율), 미달분 비이월) · 실제 평가액(입력 / 장부 근사 배지) · 목표까지 · 달성률 막대. 입출금은 손익과 분리해 표시. 장부-입력 차이가 크면 경고(자동 반영 없음).
2. **누적**: 누적 수익률(시작 대비) · 누적 손익 · 최대/현재 낙폭(입출금 제거 곡선) · 목표 달성일/일수 · 이상 복리선 대비 격차 · 입력/근사 일수.
3. **계좌 성장선**: 실제 평가액(실선) vs 이상 복리선(점선, 고정 기준). "이상선 포함/실제만" 전환, 범례, 끝점 직접 라벨, 장부 근사일 ○ 표시, 호버 십자선+툴팁, 표 보기(최근 30일).
4. **A/B 전략 비교**: 신호 수 · 응답(진입/관망/놓침/미응답) · 진입률 · 청산 거래 · 승률 · 순손익 · 건당 평균. 청산 30건 미만은 "표본 부족" 배지(실제 기록만, 모의 제외).
5. **매매일지**: LONG/SHORT 요약 카드 + 전체/LONG/SHORT 필터 + 거래 카드(방향·종목·전략·진입→청산·순손익·복기 태그·수수료/펀딩 미입력 표시). 최근 60건.
6. **데이터 확인**: 장부 불일치·장부 근사일·수수료/펀딩 미입력·추정치·범위 밖 입력·표본 부족을 숨기지 않고 나열.

## 디자인·접근성
- 모바일 우선(16px 좌우 여백, 안전 영역), 320px까지 가로 스크롤 없음(브라우저 테스트).
- 색 토큰 + 다크 모드는 별도 선택값(`prefers-color-scheme` + `data-theme`), 테마 전환 버튼. 팔레트(파랑·주황)는 `validate_palette.js`로 라이트/다크 모두 통과. 글자·배경 대비 4.5:1 이상을 브라우저 테스트로 확인.
- 색만으로 의미를 전달하지 않음: 손익은 ▲▼ 기호 + 부호, 전략은 A/B 문자 + 색 사각형, 방향은 LONG/SHORT 텍스트.
- 터치 대상 35px 이상, 키보드·스크린리더용 `role`/`aria-*`, 차트 `title/desc` + 표 보기.

## 보안·정확성
- 이 화면은 **읽기 전용**이며 계산은 모두 R2(마이크로 USDT BigInt)를 사용합니다. 새 손익식 없음(손계산 시나리오로 카드·누적·낙폭·이상선·입출금 분리를 검증).
- 소유자 확인: `RICH300_OWNER_EMAIL`(Script Properties) 미설정·방문자 이메일 불명·타인이면 빈 응답. 익명 GET이 도달 가능하다는 S0 실측을 전제로 한 fail-closed 설계.
- 챌린지 설정이 없을 때만 샘플. 설정이 있는데 데이터가 손상되면 샘플로 숨기지 않고 일반 오류 화면(내부 정보 없음).
- 자동 주문·외부 호출 없음(소스 정적 점검 테스트).
