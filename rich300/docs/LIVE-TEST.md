# 실제 환경 검증 계획 (테스트 Apps Script + 테스트 Telegram 봇)

상태: **계획 — 사용자 승인 대기.** 이 문서의 작업은 모두 *테스트 환경*에서만 합니다. 기존 radar 운영·기존 Telegram 봇·운영 웹앱·운영 Secret은 건드리지 않습니다. PR #31~#40은 병합하지 않습니다.

## 4. 완료 기준(종합 Go/No-Go)
**통과 = 아래 전부.** 하나라도 실패하면 원인·대안을 보고하고 운영 준비를 진행하지 않습니다.
1. A~C 자동 시험 전 항목 통과(B1은 ≤3초 통과, 3~10초는 경고로 R3 최적화 결정).
2. D1~D5 충족(실제 Executions 목록과 `tg:stats` 일치 확인).
3. E1~E12 중 **E11(UI 이메일)** 포함 전부 통과.
4. F1~F6 중복 0·무결성 OK.
5. G1~G7 통과(G3 실패 시 권한 조정을 사용자가 승인하고 재시험).
6. H1 확인(자정 1회 이상 관찰).
7. 시험 중 **기존 운영 봇·radar·운영 시크릿에 대한 접근·변경 0건**, 봇 토큰이 로그·저장소·결과 요약 어디에도 없음(요약 형식·`deploy.test.mjs` 점검).

**결과로 확정할 설계 결정**: ① Telegram 수신 = 폴링 유지/간격 ② UI 인증 방식(접속자 이메일 vs 대안) ③ R3 전체 시트 읽기 최적화 필요 여부 ④ 권한 범위(`drive.file` 가능 여부) ⑤ 일 마감 트리거 방식(00시+매시간 유지) ⑥ 운영 프로젝트 분리 구성 확정.

## 5. 증거와 보고
- 사용자는 `rich300LiveVerifyAuto`/`rich300LiveReport` 출력(값 없는 PASS/FAIL, ms, 카운터)을 붙여 넣습니다. 휴대폰 시나리오(E)는 `rich300LiveReport`가 시트에서 *결과를 자동 판정*하므로 사용자가 "통과" 체크를 할 필요가 없습니다.
- 저는 이를 `LIVE-RESULTS.md`에 기록하고, 판정표·결정 사항·남은 위험을 보고합니다.

## 6. 중단 조건 · 정리
- **즉시 중단**: 의도하지 않은 상대에게 메시지 발송 의심, 토큰 노출 의심, 실행 시간 한도 경고, 데이터 손상 탐지.
  → `rich300RemoveAllTriggers` 실행, BotFather `/revoke`로 **테스트 봇 토큰 폐기**(운영 봇과 무관).
- **정리(보고 후 사용자 확인 뒤에만)**: 트리거 제거, 테스트 봇 토큰 폐기 또는 유지, 테스트 시트·백업 폴더 삭제 여부. 삭제는 사용자가 확인하기 전에는 하지 않습니다.
