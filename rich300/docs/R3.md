# RICH 300 — R3 Google Sheets 저장소

`rich300/lib/schema.mjs`(엔티티·검증) + `rich300/lib/store.mjs`(추가 전용 저장·복구) + `rich300/gas/Adapters.gs`(Apps Script 포트). 시트 접근은 `env` 포트로 주입되어 같은 코드를 Node 테스트(메모리 시트)와 Apps Script가 쓴다.

## 데이터 모델
- 엔티티 시트(`Challenge, Rates, Settings, Signals, Responses, Fills, Cashflows, Equity, OpeningPositions, Reviews, Adjustments, TgUpdates`)는 **모든 리비전**을 행으로 쌓는다: `key, rev, void, recordedAt, data(정규 JSON), …사람이 보는 열`. 현재 값 = 키별 최대 rev, 취소는 `void` 리비전(삭제·덮어쓰기 없음).
- `Audit` = 진실의 원천: `seq, recordedAt, entity, key, rev, op(create|revise|void), actor, reason, before, after, prevHash, hash`. 해시 체인(SHA-256, 이전 해시 포함). `Meta`에 스키마 버전.
- 값은 **정규 십진 문자열**(`"100.0"`·`100`→`"100"`)이라 같은 값은 항상 같은 기록 — 재전송이 같은 내용이면 `duplicate`.
- 시작 설정·신호·수신 기록(`challenge, signal, tgupdate`)은 **불변**(수정·취소 거부, 다른 값 재설정은 `conflict`). 복기는 `storeSaveReview`가 계획·심리를 명시하지 않으면 거부(기본값 자동 저장 없음).

## 쓰기 프로토콜과 장애 복구
1. 스크립트 락 획득(못 얻으면 `LOCK` 오류, 아무것도 쓰지 않음) → 락 안에서 직렬화.
2. **선기록(WAL)**: ① Audit 행 추가(변경 후 전체 내용·해시) → ② 엔티티 시트 행 추가.
3. ①이 실패하면 변경 없음. ②에서 중단되면 Audit에는 있고 엔티티 시트에는 없는 상태 → **다음 쓰기(락 진입 시)가 Audit 끝부분 5건을 검사해 자동 복구**하고, 읽기는 그 사이에도 Audit 끝부분을 합쳐 최신 상태를 보여 준다(`pending`).
4. `storeIntegrityCheck`: 시퀀스·해시 체인·리비전 연속성, 엔티티 행↔Audit 일치(변조·고아·중복·누락) 검사. `storeRepair`: **Audit에는 있고 시트에 없는 행만 추가**(기존 행은 수정·삭제하지 않고 변조는 보고만). 엔티티 시트가 통째로 사라져도 Audit만으로 전부 재구성된다.
5. 시트 텍스트 서식 누락(날짜·숫자 자동 변환)은 조용히 손상시키지 않고 `INTEGRITY` 오류로 거부. 어댑터는 모든 열을 `@`(텍스트)로 만든다.

## 검증 (테스트 69건 중 R3 관련 25건)
- **고장 주입 전수 시험**: 11개 연산(챌린지·신호·응답·체결·수정·취소·입출금·평가액·복기·텔레그램 선점) 순서의 *쓰기 지점마다* 한 번씩 실패시키고 재시도 → 최종 상태(감사 로그 + 모든 시트)가 정상 실행과 **바이트 단위로 동일**, 무결성 통과.
- 중복(같은 내용)·충돌(다른 내용)·잠금 충돌·예외 후 락 해제·변조 탐지·감사 로그만으로 복원 + R2 장부 결과 동일.
- GAS 경로: 엔진 번들 + `Adapters.gs`를 모듈 없이 vm에서 실행, **텍스트 서식이 없으면 숫자·날짜로 바꾸는 가짜 SpreadsheetApp**에서 날짜 키 왕복·헤더 불일치·락·복구.

## 한계
- 쓰기 1건이 시트 전체를 읽는다(O(N)). 메모리 환경 기준 이력 2,500건에서 쓰기 1건 ≈ 22ms, 장부 전체 계산 66ms. **Apps Script에서는 시트 읽기 지연이 지배적**(쓰기당 몇 번의 읽기)이라 수천 행 규모에서 쓰기당 1~3초가 될 수 있다 → S0에서 실측하고, 필요하면 키 열만 읽거나 끝부분만 읽는 포트로 최적화(인터페이스 불변).
- Sheets는 단일 쓰기 안에서 두 시트를 원자적으로 쓸 수 없다 → 선기록 + 복구로 보완(위).
- 사용자가 시트를 직접 편집하면 방지가 아니라 **탐지**(무결성 검사).
- 락은 스크립트 단위 락(`LockService`), 대기 최대 10초.
