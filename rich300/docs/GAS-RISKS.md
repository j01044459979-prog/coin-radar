# Apps Script 호환성 위험 검토 (R4·R6·R7·R8)

이 환경에서는 `script.google.com`에 접속할 수 없어 **실제 Apps Script에서 실행해 보지 못했습니다.** 아래 "근거" 열은 확인 수준을 구분합니다.
- **S0 실측**: 사용자 Google 프로젝트에서 Actions로 측정(`S0-RESULTS.md`)
- **오프라인 시험**: Node vm 가짜 Apps Script 서비스로 검증(실제 서비스 동작은 아님)
- **미확인 가정**: 문서·경험에 기반한 가정, 테스트 프로젝트에서 확인 필요

| # | 대상 | 위험·가정 | 근거 | 영향 | 완화·확인 방법 |
|---|---|---|---|---|---|
| 1 | 라우터·UI 접근 | `Session.getActiveUser().getEmail()` 이 *접속한 사용자로 실행* 배포에서 방문자 이메일을 돌려준다 | **미확인**(S0 ④ 미실측) | 안 돌려주면 소유자도 UI에 못 들어감(fail-closed라 보안은 안전, 사용성 문제) | `rich300SelfTest` 의 `owner-visible` 경고, UI URL을 본인 계정으로 열어 확인 |
| 2 | API 배포(나로 실행/익명)에서 UI 접근 차단 | 익명·타인은 이메일을 알 수 없어 `?p=…` 페이지가 빈 응답 | 오프라인 시험(타인·익명·미설정 모두 빈 응답) + S0 실측(익명 GET은 정상 리다이렉트, 정보 없음) | 정보 노출 없음 | 테스트 프로젝트에서 시크릿 창으로 재확인 |
| 3 | 한 프로젝트에 두 웹 앱 배포(API/UI) | 배포별 설정(나로 실행 vs 접속자로 실행)이 공존 | **미확인**(S0 가정) | 불가하면 UI/API를 별도 프로젝트로 분리해야 함(코드는 분리 가능하게 라우터 구성) | S0 ④ |
| 4 | `google.script.run` | 서버 함수 이름이 밑줄로 끝나면 클라이언트에서 호출 불가 | 오프라인 시험(화면이 부르는 모든 함수가 번들에 존재·밑줄 없음) | 화면 동작 불가 | 테스트 프로젝트에서 폼 제출 1회 |
| 5 | `google.script.run` 서버 함수의 소유자 확인 | 클라이언트 호출은 라우터를 거치지 않음 | 오프라인 시험(타인·익명 `forbidden`, 시트 미변경) | 우회 쓰기 방지 | 각 서버 함수가 개별 확인(구현됨) |
| 6 | HtmlService 샌드박스 | 인라인 `<script>`·`crypto.randomUUID`·CSS `:where()`·`prefers-color-scheme` 가 iframe 안에서 동작 | 오프라인 시험(Chromium) — Apps Script iframe과 다를 수 있음 | 폼/필터/차트 상호작용 일부 불가 가능 | 폴백: `randomUUID` 없으면 시간+난수(구현됨). 테스트 프로젝트에서 모바일 브라우저로 확인 |
| 7 | 서버 렌더링 HTML 크기 | 일지·대시보드 페이지 100KB 미만(1년치 모델) | 오프라인 시험(크기 상한 단언) | 느린 로딩 | 일지 최근 40건·대시보드 최근 60건만 |
| 8 | 시트 읽기 시간 | R3가 전체 시트를 읽음(요청마다) — 행이 늘면 느려짐 | 오프라인 1년치 0.1~1초 / **Apps Script 시간 미측정**(`s0EngineBench` 상세 값 미확인) | 6분 실행 한도·트리거 시간 한도 | R3 최적화 여부는 S0 결과 후 결정(보류) |
| 9 | 시간 트리거 정확도 | `atHour(0)` 은 00:00~01:00 사이 임의 시각 실행 | 문서 가정, `s0Daily` 미관측(`daily=[]`) | 마감이 최대 1시간 늦을 수 있음(날짜 경계 계산은 시각 무관) | 마감을 **멱등**으로 설계 + 매시간 재확인(오프라인 시험: 놓친 날 순서대로 1회씩) |
| 10 | 1분 폴링의 일일 실행 시간 | 트리거 총 실행 시간 한도(문서상 90분/일 — 미검증 가정) | S0 초기 값(maxMs=3917)만 있음. 이 값은 **카운터 보고값이며 729회 실제 자동 실행으로 확정하지 않음** | 한도 초과 시 트리거 중단 | `tg:stats`(실행 수·총/최대 ms·느린 실행)로 실측, 한도 근접 시 폴링 간격 확대(적응형은 미구현·후속) |
| 11 | 겹친 실행 | 1분 트리거 실행이 길어지면 겹침 | 오프라인 시험(사용자 락 선점 시 건너뜀, 저장소 락과 별개) + 퍼징(순차 중복) | 이중 처리 | 사용자 락 + kv 리스(55초) + 저장소 락 + 유일키(구현됨). **진짜 병렬 실행은 오프라인에서 재현 불가** |
| 12 | Script Properties | 값 9KB·총 500KB 한도, 쓰기 지연 | 오프라인 시험(GC 동작), 한도는 **미검증 가정** | 초안·실패 카운터 누적 | `tgGc`(만료 정리), kv 키 수 작음. 정기 점검 항목 |
| 13 | 락 경합 | `LockService` 스크립트 락 10초 대기 후 LOCK 오류 | 오프라인 시험(LOCK은 아무것도 쓰지 않고 재시도로 수렴, 퍼징) | 일시적 실패 | 재처리 설계(구현됨). 실제 경합 시간 미측정 |
| 14 | UrlFetch | `muteHttpExceptions`·429·타임아웃, 일일 호출 한도(문서상 2만 — 가정) | 오프라인 시험(오류 분류·재시도) | 일시적 전송 실패 | 지수 대기 최대 3회, 긴 `retry_after` 는 다음 틱 |
| 15 | 토큰 노출 | 네트워크 예외 메시지에 URL(토큰 포함)이 들어갈 수 있음 | 오프라인 시험(메시지 폐기·상태 코드만 반환, 로그·속성에 없음) | 토큰 유출 | 어댑터 안에서만 사용(구현됨) |

## 결론
- 보안 측면(소유자 확인 fail-closed, 서버 함수 개별 확인, 토큰 비노출, 환경 가드)은 오프라인에서 모두 시험했고 실패 시 *닫히는* 방향입니다.
- **실제 환경 확인이 필요한 최소 항목**: #1/#3(UI 이메일·두 배포), #6(HtmlService 화면 동작), #9/#10(트리거 시각·실행 시간), #17(BigInt), #18(drive.file). 모두 테스트 프로젝트에서 사용자 조작 약 10분으로 확인 가능하며 `PREFLIGHT.md` B에 포함했습니다.
