상태: **부분 완료**. Actions 쪽(외부→Apps Script) 실측은 끝났고, Google 편집기에서만 실행되는 4개 항목은 미측정입니다.
작성자 표기: 아래 Actions 실행(#4, #5, #7)과 `test/rich300-s0-measurements` 브랜치 커밋은 저장소 소유 계정으로 기록되어 있으나, 누가 수행했는지는 확인되지 않았으므로 단정하지 않습니다.
Secret·URL·본문은 기록하지 않았습니다(로그에는 호스트 이름과 수치만 남음).

## 1. 실측된 항목 (API 웹앱 배포, 실행 주체 = 배포자, 접근 = 누구나)
근거: Actions run #5 (`test/rich300-s0-measurements`, 라이브 단언 통과), run #7 (`feature/rich300-r5-api`, 익명 GET 판별 추가).

### 익명 GET의 의미
- 로그인 화면이 아니라 JSON 응답이므로, 배포 설정(누구나)대로 동작합니다.
- 따라서 운영 `Api.gs`의 `doGet`은 인증 실패와 동일한 균일 응답(`unauthorized`)만 돌려주고 시트를 열지 않아야 합니다(R5 설계와 일치). S0 프로브의 `doGet`은 카운터를 반환하는 측정용이므로 운영에 가져가지 않습니다.
- 운영 UI는 별도 배포(접속자 인증)로 분리합니다. 이 항목은 아래 미측정 ④에서 확인합니다.

## 2. 미측정 항목과 최소 작업 (Google 편집기에서 직접 실행 필요)
이미 만든 테스트 프로젝트를 그대로 씁니다. 새 프로젝트·새 배포는 만들지 않습니다.

| # | 항목 | 실행 위치 | 작업 | 결과 확인 방법 |
|---|---|---|---|---|
| ① | `s0Compat` (BigInt·V8 문법·SHA-256) | Apps Script 편집기 | 함수 선택 `s0Compat` → 실행 | 실행 로그 전체 복사 |
| ② | `s0EngineBench` (엔진 성능) | 편집기 | 함수 선택 `s0EngineBench` → 실행 | 실행 로그 전체 복사 |
| ③ | `s0InstallTriggers` (1분·일일 트리거 시각·소요) | 편집기 | `s0InstallTriggers` 실행(권한 승인 1회) → 1시간 이상 방치 → `s0Report` 실행 | `s0Report` 로그 |
| ④ | UI 방문자 이메일 | 편집기 + 브라우저 | 배포 관리에서 두 번째 배포를 "웹 앱 / 실행: 접속한 사용자 / 접근: Google 계정 보유자"로 추가 → 그 URL을 본인 계정으로 열기 | 화면에 표시된 이메일 일치 여부(O/X) |

로그에는 금액·ID·Secret이 없으므로 그대로 붙여 주시면 됩니다. 트리거는 측정 후에도 지우지 않고, 정리는 별도 승인 때만 합니다.
①②는 1~2분, ③은 승인 후 방치(수 분 + 대기), ④는 약 3분입니다.

## 3. 잠정 판단 (미측정 항목이 나오면 확정)

### Telegram 수신 방식: **폴링 권장 (웹훅 제외)**
- 웹훅은 Apps Script 웹앱을 URL로 지정하게 되는데, 실측상 POST가 302로 응답합니다. Telegram이 이 리다이렉트를 따라가는지는 이 환경에서 검증하지 못했으므로 "따라가지 않을 위험"으로 둡니다.
- 헤더를 읽을 수 없어서 Telegram 웹훅의 `secret_token` 헤더로 발신자를 검증할 수 없습니다(실측). 본문만으로는 위조 요청을 막을 수단이 약합니다.
- 두 가지가 겹치므로 웹훅은 채택하지 않습니다. 폴링의 실행 주체(Apps Script 시간 트리거 vs GitHub Actions)는 ③의 트리거 지연·소요 실측으로 결정합니다. Actions 폴링은 스케줄 지연이 커서 버튼 응답이 느릴 수 있습니다. 어느 쪽이든 실제 Telegram 호출은 이 단계에서 하지 않습니다.

### R3 성능 최적화
- 쓰기 비용이 작고(p50 약 0.4 s) 직렬화도 정상이라 **쓰기 쪽은 최적화 불필요**.
- 전체 시트 읽기는 ②의 엔진 시간과 시트 행 수 증가 곡선을 본 뒤 결정합니다. 현재는 보류.

### 확정된 설계
본문 HMAC(서명 포함 시각·nonce), 리다이렉트 추적 클라이언트, 익명 도달 가능한 API의 균일 거부 응답, UI와 API 배포 분리.
