# 실전 감시 관리 (?p=ops)

소유자 전용. Apps Script 편집기를 쓰지 않고 실전 감시를 켜고 끈다. 열기만 해서는 아무것도 바뀌지 않는다.

## 흐름
1. **사전 점검**(읽기 전용): 운영 환경 · Telegram 토큰/페어링/전송 가드(운영 승인 외 차단 사유 없음) · OKX/Bybit 시세 연결 · 감시 미리보기. 메시지·트리거·감시 설정을 바꾸지 않고, 통과 기록(`ops:precheck`, 15분·같은 빌드)만 남긴다.
2. **실전 감시 시작**: 확인 문구 `실전 감시 시작` 입력 후 → 서버가 소유자·문구·점검 기록·Telegram 준비를 다시 검증 → `RICH300_PROD_APPROVED=yes` → 5분 감시 트리거 **정확히 1개** 설치 → `RICH300_WATCH_ALERTS=on`(마지막) → 속성·트리거 재조회로 확인. 실패하면 감시 off · 트리거 제거 · 운영 승인 이전 상태로 복원(복원 확인까지 실패하면 `rollback-failed` 표시).
3. **감시 중지**: `RICH300_WATCH_ALERTS=off` 후 트리거 제거, 재조회로 확인. 락을 못 잡아도 진행한다. 운영 승인 플래그·시트·Telegram 연결 정보는 그대로 둔다.

## 안전 장치
- 바꿀 수 있는 속성은 `RICH300_PROD_APPROVED`(값 `yes`)와 `RICH300_WATCH_ALERTS`(`on`/`off`), 내부 기록 `ops:precheck`·`ops:last` 뿐(서버 허용 목록). 화면에서 호출되는 함수는 이름·값을 인자로 받지 않는다.
- 스크립트 락으로 중복 클릭·동시 실행 차단(`busy`). 이미 켜져 있으면 `already-on`(변경 없음).
- 포지션 0건이면 정상 대기(시세 호출 없음). 자동 주문 없음. 토큰·채팅 ID·가격은 화면·로그·반환값에 없다.
- 중지 직후에도 이미 실행 중이던 한 번의 감시 실행은 끝까지 갈 수 있다(최대 한 번의 실행 분량).
