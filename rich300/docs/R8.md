## 1. Google Sheets 자동 백업
- **방식**: 스프레드시트 사본(`RICH300-backup-YYYYMMDD-HHmm`, KST)을 Drive 폴더 `RICH300-backups`에 만든다. 저장소 락 안에서 복사하므로 쓰기 도중의 사본이 생기지 않는다.
- **검증(필수)**: 사본을 열어 ① 무결성 검사(감사 해시 체인·행 일치) 통과 ② 원본과 *지문* 일치(감사 로그 개수·마지막 해시·시트별 행 수·스키마). 지문에는 금액·ID가 없다.
- **트리거**: 주 1회(일요일 03시 KST) + 수동 실행(`rich300BackupRun`). 같은 분에 다시 실행해도 `exists`로 한 번만 만든다.
- **실패 정책**: 사본 생성 실패/검증 실패 → 사본을 휴지통으로 보내고 **기존 백업은 건드리지 않음**. 락 경합은 아무것도 만들지 않고 다음 실행에서 재시도. 원본에 무결성 문제가 있으면 사본은 *증거로 남기되* **회전(삭제)하지 않음**(좋은 과거 백업 보존).

## 2. 최근 8개 유지
- 설정 `backupKeep`(기본 8, 1~30으로 보정). 이름에 든 시각이 최신인 N개를 남기고, **이름 패턴이 정확히 맞는 백업만** 휴지통으로 이동(복구 가능). 백업 폴더의 다른 파일·복원본(`RICH300-restored-…`)·운영 시트는 삭제 대상이 아님. 12주 연속 실행 시 8개만 남는 것을 테스트로 확인.

## 3. 복원·무결성
- **복원은 새 사본 생성까지**: 백업 → `RICH300-restored-…` 사본 → 무결성·지문 재검증. 운영 시트를 덮어쓰지 않는다. 손상된 백업(변조)은 복원을 거부하고, 백업 폴더 밖 파일은 복원 대상이 아니다.
- **운영 시트 전환**은 별도 명시 단계: 사용자가 Script Property `RICH300_SWITCH_TO`(새 시트 ID)와 `RICH300_SWITCH_CONFIRM=yes`를 직접 설정하고 `rich300BackupSwitchFromProps`를 실행해야 한다. 전환 전 ① 대상 무결성·환경 표식(test/prod) 점검 ② 현재 시트 자동 백업 ③ 이전 시트 ID를 `RICH300_SHEET_ID_PREVIOUS`에 보관(되돌리기).
- 시험: 복원본의 R2 장부 계산이 원본과 동일, 백업 이후 변경분은 복원본에 없음, 운영 시트·기존 백업 불변.

## 4. Telegram CSV 자동 전송 = OFF
구현하지 않았습니다(코드에 CSV·네트워크·Telegram 호출 없음, 테스트로 고정). 설정 `backupTelegramCsv=on`이어도 아무것도 보내지 않고 `telegram-csv-unsupported` 경고만 반환합니다.

## 8. 테스트 프로젝트와 운영 프로젝트 분리
- **서로 다른 Apps Script 프로젝트·스프레드시트·봇 토큰**을 쓴다(공유 금지).
- `RICH300_ENV = test | prod`와 시트 `Meta.envName` 표식이 일치해야 한다(불일치 시 자가 점검 실패, 시트 전환 점검 거부). 운영 데이터를 테스트 프로젝트에 연결하는 실수·그 반대를 막는다.
- **Telegram 호출 가드**(fail-closed): 환경 미설정/오타 → 차단, 운영 → `RICH300_PROD_APPROVED=yes`일 때만, 테스트 → `RICH300_TEST_TG_ALLOW=yes`일 때만 허용. 승인 전에는 네트워크 호출 자체가 없다(가드 파일이 없어도 차단).
- 테스트 프로젝트에 운영 승인 플래그가 있으면 자가 점검이 **실패**로 알린다.
