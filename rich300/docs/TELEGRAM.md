# RICH300 Telegram 연결 준비 (화면: `?p=tg`)

## 1) COIN RADAR 봇을 RICH300 에서 재사용해도 되는가
- **가능**: COIN RADAR(`radar-service`)는 `sendMessage` 계열 전송만 하고 `getUpdates`·`setWebhook` 을 쓰지 않는다(저장소 검색으로 확인). RICH300 은 웹훅 없이 `getUpdates` 폴링만 쓴다(Apps Script 웹앱은 헤더를 못 읽어 웹훅 불가). 한 봇에서 둘이 충돌하지 않는다.
- **분리되는 것**: 알림 정책과 상태 저장은 이미 분리되어 있다 — COIN RADAR 는 GitHub Actions 캐시(`.radar-state`), RICH300 은 Script Properties(`tg:`·`w:`·`tgdiag:` 접두). RICH300 은 *페어링된 소유자 1명*의 메시지만 처리한다.
- **주의**: ① 같은 봇의 `getUpdates` 는 RICH300 만 읽어야 한다(다른 소비자 추가 금지). ② 토큰이 두 곳(GitHub Secret, Script Properties)에 있다 — 토큰을 바꾸면(BotFather 재발급) 둘 다 바꿔야 한다. ③ 추천 버튼 연동(`RADAR_RICH300_BUTTONS`)을 쓰려면 같은 봇이어야 한다. 버튼 연동이 필요 없고 완전한 분리를 원하면 BotFather 에서 RICH300 전용 봇을 새로 만드는 쪽이 더 안전하다(토큰 폐기·권한을 따로 관리).

## 2) 토큰을 GitHub Secret 에서 Script Properties 로 "옮기는" 자동화를 만들지 않은 이유
GitHub Secret 은 쓰기 전용이라 누구도(저 포함) 값을 읽을 수 없다. 워크플로가 값을 꺼내 Apps Script 로 보내려면 ① 값을 로그·아티팩트에 찍거나 ② 인증이 필요 없는 수신 주소를 새로 열어야 한다(웹앱은 "나만" 접근이라 외부 호출 불가). 둘 다 노출 위험이 커서 만들지 않았다. 대신 **BotFather 에서 토큰을 다시 보고**(`/mybots` → 봇 선택 → API Token) 소유자 전용 입력창에 붙여 넣는다 — 값은 브라우저에서 서버로만 전달되고 화면·URL·로그·반환값에 나오지 않는다.

## 3) 연결 순서 (`?p=tg`, 소유자 로그인 상태에서)
1. **토큰 등록** — 입력창에 붙여 넣고 저장(토큰이 아직 없을 때만 보이는 입력창. 형식 확인 → 저장 → 가드가 허용하면 `getMe` 로 확인, 거절되면 저장 취소).
2. **테스트 전송 허용** — `테스트 전송 허용` 문구를 입력해 `RICH300_TG_TEST_OK=yes`. **운영 승인(`RICH300_PROD_APPROVED`)과 별개**이며 이 화면은 운영 승인을 절대 바꾸지 않는다.
3. **연결 읽기 점검** — `getMe`·`getWebhookInfo` 두 호출(메시지 없음). 웹훅이 설정돼 있으면 폴링과 충돌하므로 알려 주기만 하고 바꾸지 않는다.
4. **페어링** — `코드 만들기`(10분·1회용) → Telegram 에서 봇에게 `/start 코드`(개인 대화) → `페어링 확인`(getUpdates **1회**). 답장 메시지는 보내지 않고, 코드 생성 이후의 `/start 코드` 외에는 처리하지 않는다. 폴링 트리거는 설치하지 않는다.
5. **테스트 메시지 1건** — `[RICH300 TEST]`. 1회용 nonce·락·보내기 전 pending 기록으로 중복 방지. 실패/못 받음일 때만 다시(최대 3회).
6. **수신 확인** — `받았음`/`못 받음`. API 전송 성공과 사용자의 실제 수신 확인은 별도로 기록된다.

## 4) 가드 구조 (운영 승인과 테스트 전송 분리)
| 호출 | 운영 승인 없음 | `RICH300_TG_TEST_OK=yes` | 운영 승인 `yes` |
|---|---|---|---|
| getMe · getWebhookInfo | 차단(읽기 승인 속성이 있으면 허용) | 허용 | 허용 |
| getUpdates | 차단 | **`?p=tg` 페어링 확인(purpose=pair-poll)일 때만** | 허용 |
| sendMessage | 차단 | **`?p=tg` 테스트 전송(purpose=test-send) 1건 동안만** | 허용 |
| 폴링 트리거·감시 알림·버튼 응답·마감 알림 | 차단 | **차단** | 허용 |
purpose 는 화면의 명시적 동작이 실행되는 동안에만 설정되고 끝나면 초기화된다. 트리거에서 도는 코드는 purpose 를 설정하지 못하므로 테스트 허용만으로는 감시 알림이 나가지 않는다.

## 5) 되돌리기
- 테스트 허용 끄기: `?p=tg` 의 `허용 해제` 또는 속성 `RICH300_TG_TEST_OK` 삭제.
- 토큰 폐기: BotFather 에서 `/revoke` 후 속성 `RICH300_TG_TOKEN` 삭제(교체는 편집기에서; 이 화면은 토큰이 이미 있으면 덮어쓰지 않는다).
- 페어링 해제: 속성 `tg:paired` 삭제.

## 6) 아직 하지 않는 것
감시 트리거 설치, `RICH300_WATCH_ALERTS` 켜기, 운영 승인(`RICH300_PROD_APPROVED`), 추천·포지션 알림 활성화 — 모두 별도 승인.
