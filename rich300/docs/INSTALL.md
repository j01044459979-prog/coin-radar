# RICH 300 설치(운영) — 사용자가 하는 일

별도 테스트 봇은 만들지 않습니다. **기존 운영 봇 하나**를 씁니다. 아래 순서대로 하면 됩니다. 스크린샷·로그를 보내실 필요는 없습니다(마지막 점검 화면의 복사용 요약 1회만).
※ 이 문서의 단계는 **운영 전환 승인 후**에 진행합니다(코드 분석·개발·테스트·Draft PR까지만 승인된 상태에서는 하지 않습니다).

## 준비물
- 기존 Google 계정(Apps Script·Sheets·Drive 사용)
- 기존 Telegram 봇 토큰(GitHub Secret `TELEGRAM_BOT_TOKEN` 과 같은 값 — 값을 어디에도 붙여 넣어 공유하지 마세요)

## 설치 방법 (권장 순서)
| 우선 | 방법 | 사용자 작업 | 권한 | 비고 |
|---|---|---|---|---|
| **1 (권장)** | **clasp 설치 스크립트** (`rich300/deploy/clasp-install.sh`, Cloud Shell) | Cloud Shell 열기 → 명령 1줄 붙여 넣기 → Google 로그인·승인 | **`script.projects`·`userinfo.email` 두 범위만**(clasp 기본 로그인은 `cloud-platform` 등 더 넓은 범위를 요청하므로 스크립트가 줄여서 요청), 끝나면 자동 로그아웃 | 사용자 설정의 Apps Script API 토글이 이 경로에서 쓰입니다(이미 켬) |
| 2 | 부트스트랩 v2 (작은 파일 2개 붙여 넣기 + 실행) | 붙여 넣기 2개 + 실행 + 권한 승인 | `script.projects`·`drive.scripts`·`drive.file`(전체 Drive 아님) | Apps Script API 경로는 기본 Cloud 프로젝트 문제로 막힐 수 있고, Drive 대체 경로는 실제 동작 미검증 |
| 3 (최후) | 큰 `Code.gs` 한 번 붙여 넣기(**Copy raw file** 버튼) | 붙여 넣기 3개 | 없음 | 가장 단순하지만 손 복사 |

### 1) clasp 설치 스크립트 (권장)
프로젝트 ID 와 커밋(40자)은 **기본값 없이 직접 넘깁니다**. 프로젝트 ID 는 편집기 주소 `https://script.google.com/home/projects/<ID>/edit` 의 `<ID>` 입니다(Drive 파일 ID 와 다를 수 있으니 편집기 주소에서 복사하세요).
1. <https://shell.cloud.google.com> 을 열고(프로젝트를 만든 Google 계정, 처음이면 약관 동의) 보고서의 한 줄 명령에 `ID` 만 채워 실행합니다. 스크립트와 설치 파일은 모두 지정한 **그 커밋 그대로**만 사용합니다. **반드시 파일로 받아 실행**하는 형태(`curl -o … && bash …`)여야 합니다 — `curl … | bash` 로 실행하면 clasp 의 로그인 프롬프트가 스크립트 자신을 입력으로 읽어 `Missing code in response URL` 로 실패합니다.
2. 안내된 로그인 주소를 열어 승인합니다(요청 권한은 Apps Script 프로젝트 관리와 이메일 확인뿐). 승인 뒤 '사이트에 연결할 수 없음' 같은 페이지가 뜨는 것이 정상이며, 그 주소창의 `http://localhost:8888/?code=…` 로 시작하는 URL 전체를 **터미널**에 붙여 넣습니다(일회용 코드가 들어 있으니 채팅에는 공유하지 마세요). 내 PC 에서 실행하면 이 붙여 넣기 없이 자동 완료됩니다.
3. 스크립트가 **현재 내용을 `~/rich300-backup-…` 에 백업**하고, 대상 프로젝트 ID·현재 원격 파일·변경 계획(교체/추가/삭제)을 보여 준 뒤, ID 의 **마지막 6글자를 입력**해야 진행합니다. 원격이 RICH300 부트스트랩/설치 상태가 아니면(다른 프로젝트·S0 등) 아무것도 바꾸지 않고 중단합니다.
4. 먼저 원격이 **부트스트랩 상태인지 이미 설치 완료 상태인지** 판별해 보여 주고(이미 같으면 push 없이 PASS), push 후에는 서버 반영 지연을 고려해 여러 번 다시 내려받아 내용이 같은지 확인합니다(Code·Fill 은 줄바꿈 차이 무시, 매니페스트는 키 순서와 무관한 의미 비교). 다르면 어느 파일이 어떻게 다른지(크기·해시 앞 12자리·첫 차이 줄)를 보여 주고, **다르거나 실패하면 백업으로 자동 복구**한 뒤 복구 결과도 확인합니다(복구가 안 되면 백업 폴더와 수동 복구 명령을 알려 줍니다). 끝나면 로그아웃(토큰 삭제).
5. `[PASS] 반영 완료` 후 편집기를 새로고침 → 함수 `rich300Install` 실행. 새 프로젝트 생성·삭제·배포·Telegram 호출은 없습니다.
6. push 가 실패하면: clasp 는 Google 오류 본문을 줄여 보여 주므로, 스크립트가 같은 요청(`projects.updateContent`, 같은 파일 3개)을 Apps Script API 로 직접 보내 **HTTP 상태·오류 본문**을 그대로 출력하고(토큰·client secret 은 출력 안 함) 흔한 원인(API 꺼짐·계정 불일치·로그인 만료·매니페스트 거부)을 안내합니다. 그 직접 호출이 성공하면 반영된 것으로 보고 다시 내려받아 일치를 확인합니다. 둘 다 실패하면 원격이 바뀌지 않았는지 확인하고 백업 기준으로 복구합니다. clasp 는 PATH 의 clasp 3.x(예: 3.4.1)를 그대로 쓰고, 없으면 `RICH300_CLASP_VERSION`(기본 3.4.1)으로 고정한 npx 를 씁니다.

### 2) 부트스트랩 v2
큰 `Code.gs`(약 2,700줄)를 손으로 복사하면 끝부분이 잘리는 사고가 날 수 있습니다(`SyntaxError: Unexpected end of input`). 아래 방법은 **작은 파일 2개(합쳐 7KB)만** 붙여 넣고, 나머지는 프로젝트가 스스로 GitHub 에서 받아 **SHA-256 확인 → 문법 검사 → 자기 자신에 반영**합니다. 하나라도 어긋나면 아무것도 바꾸지 않습니다.
| # | 할 일 |
|---|---|
| A | (선택) <https://script.google.com/home/usersettings> 의 **Google Apps Script API** 토글. 이 토글은 `clasp` 같은 외부 도구용이고, 스크립트가 자기 자신을 고치는 호출은 **스크립트의 Cloud 프로젝트**에서 API 가 켜져 있어야 합니다(기본 프로젝트는 사용자가 켤 수 없음). 그래서 이 토글을 켜도 B4 가 실패할 수 있고, 그때는 부트스트랩이 자동으로 **Drive 경로(B5)** 로 넘어갑니다 |
| B | 기존 `RICH300` 프로젝트에서 `Code.gs` 전체를 `rich300/apps-script-bootstrap/Code.gs`(Raw, 12KB) 내용으로 교체, `appsscript.json` 을 `rich300/apps-script-bootstrap/appsscript.json`(약 350바이트) 내용으로 교체. GitHub 파일 화면 오른쪽 위의 **Copy raw file** 버튼을 쓰면 끝부분이 잘리지 않습니다 |
| C | 함수 `rich300Bootstrap` 실행(권한 동의 — 이 임시 설치 도구는 `drive.scripts`·`drive.file` 권한(전체 Drive 아님)을 요청합니다. 이 프로젝트 파일 하나만 읽고 덮어쓰며, 설치 후 최종 매니페스트에는 없는 권한입니다) → 실행 로그에 `B1 B2 B3 PASS` 와 `B4` 또는 `B5` 결과 |
| D | `B4 PASS`(Apps Script API) 또는 `B5 PASS`(Drive 경로, 쓴 뒤 다시 읽어 내용 일치 확인)이면 편집기를 새로 고침 → `Code.gs`·`Fill.html`·`appsscript.json` 이 설치 파일로 바뀌어 있습니다 |
이후는 아래 순서의 **3번(배포)** 부터 이어서 합니다(1~2번은 이미 끝난 것). 부트스트랩은 Telegram·시트·Drive 에 접근하지 않고 웹 앱 배포도 하지 않습니다. 설치 후 <https://myaccount.google.com/permissions> 에서 이 스크립트의 `script.projects`·Drive 권한을 철회해도 됩니다(최종 매니페스트에는 없는 권한입니다).

## 순서
| # | 할 일 | 소요 |
|---|---|---|
| 1 | <https://script.google.com> → 새 프로젝트 `RICH300`. 저장소 `rich300/apps-script/` 의 파일 3개를 붙여 넣기: `Code.gs`(기존 내용 교체), `Fill.html`(파일 추가 → HTML, 이름 `Fill`), `appsscript.json`(프로젝트 설정 → "appsscript.json 매니페스트 파일 표시" 후 교체) | 3분 |
| 2 | 프로젝트 설정 → 스크립트 속성 2개 추가: `RICH300_TG_TOKEN` = 기존 운영 봇 토큰, `RICH300_TG_READONLY_OK` = `yes`(**읽기 전용 점검 승인**: 봇 정보·웹훅 조회 두 호출만, 메시지·수신·설정 변경 없음) | 1분 |
| 3 | 배포 → 새 배포 → 유형 *웹 앱* → 실행: **접속한 사용자** · 액세스: **나만** → 배포(권한 동의) | 2분 |
| 4 | 함수 `rich300Install` 실행(권한 동의). 시트·챌린지(300 USDT, 일 5%)·마감/백업 트리거·자동 검증·**봇 사전 점검(웹훅·다른 소비자 확인)** 이 한 번에 됩니다. 메시지 전송·폴링은 아직 0건 | 1분 |
| 5 | 웹 앱 주소 끝에 `?p=ping` → `verdict: OK` 인지, `?p=check` → **전체 판정** 확인(자동 검증은 몇 분 뒤 완료). 이상이 있으면 여기서 멈추고 알려 주세요 | 1분 |
| 6 | **(운영 승인 후)** 스크립트 속성 `RICH300_PROD_APPROVED` = `yes` → `rich300Install` 다시 실행 → 실행 로그에 **페어링 링크** | 1분 |
| 7 | 휴대폰에서 페어링 링크 탭 → 봇이 "연결됨" 응답(10분 안, 1회용, 본인만) | 10초 |
| 8 | **(radar 연동 승인 후, 별도)** GitHub 저장소 변수 `RADAR_RICH300_BUTTONS` = `on` (신호 알림을 쓰려면 `RADAR_SIGNAL` = `on` 이어야 함). 변수를 지우면 즉시 이전과 같습니다 | 1분 |

웹 앱 화면: `…/exec?p=dash`(홈) · `?p=journal`(일지) · `?p=signals`(추천) · `?p=stats`(성적) · `?p=assets`(자산: 평가액·입출금) · `?p=check`(점검) · `?p=ping`(배포·본인 확인 진단). 홈 화면에 추가해 두면 편합니다.

## 문제가 생기면
| 증상 | 확인 |
|---|---|
| 웹 앱이 빈 화면 | 배포가 *접속한 사용자 / 나만* 인지, 소유자 Google 계정으로 열었는지(이메일을 못 읽으면 안전하게 빈 응답) |
| `rich300Install` 이 웹훅 오류로 멈춤 | 이 봇에 이미 웹훅이 있음. 지우지 않고 멈춘 것입니다 — 알려 주세요 |
| 버튼을 눌러도 반응이 늦음 | 폴링은 최소 1분 간격 → 최대 약 1분. `?p=check` 의 폴링 실측 확인 |
| 입력 화면 링크가 로그인을 요구 | Telegram 내장 브라우저 때문. `/fill`·`/exit` 명령은 Telegram 안에서 그대로 됩니다 |

## 멈추기·되돌리기(삭제 없음)
- radar 쪽: `RADAR_RICH300_BUTTONS` 변수 삭제(또는 `off`) → 메시지가 이전과 동일.
- 앱 쪽: 속성 `RICH300_PROD_APPROVED` 삭제 → Telegram 호출 즉시 0건. 함수 `rich300RemoveAllTriggers` → 폴링·마감·백업 트리거 제거. 시트·백업은 그대로 남습니다.

## 할당량(공식 문서 기준 가정값 — 실측은 `?p=check`)
폴링 1분 간격 ≈ 하루 1,440회 × 약 1초 = 약 24분(트리거 합계 한도 90분/일의 1/4). 일 마감·주간 백업은 하루 수 초~수십 초. 한도에 가까워지면 폴링 간격을 5분으로 늘리는 것이 안전합니다(`rich300TgInstallPollTrigger(5)`).
