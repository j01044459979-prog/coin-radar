# RICH 300 CHALLENGE 1.0 — 설계 (Google Apps Script + Google Sheets, 초안)

> 상태: 설계 초안(승인 대기). 거래소 API 연동·자동 주문 없음. 기존 radar 스케줄·알림·전략은 변경하지 않는다. main 병합·실제 Telegram 발송·웹앱 운영 배포는 각각 별도 승인.
> 승인된 설정: GAS+Sheets 우선 · 기존 봇 토큰 재사용(Secret에서만) · 허용 사용자 본인 1명(ID 하드코딩 금지) · Asia/Seoul · 일 마감 00:00 KST · 시작 300 USDT · 목표 5%(변경 가능) · 브랜치 `feature/rich300-journal` · 모듈 `rich300/`.
> 이 설계는 `JOURNAL-3-1`/Cloudflare 안(이전 보고)을 대체한다.

## 0. 확인된 사실과 **검증이 필요한 가정**
| 구분 | 내용 |
|---|---|
| 확인(저장소) | 저장소는 public(코드·Actions 로그 공개). radar는 Telegram **발송만** 하고 `getUpdates`/웹훅 코드 없음. 토큰은 GitHub Secret `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`에만 있음 |
| 가정(GAS 동작, 이 환경에서 접근 불가 → **S0 스파이크에서 실측**) | ① 웹앱 `doPost`는 HTTP 헤더를 읽을 수 없음(쿼리·본문만) ② POST 응답은 302 리다이렉트로 전달되어 Telegram 웹훅이 "비정상 응답"으로 보고 재전송할 수 있음 ③ 개인 Google 계정에서 "나로 실행"이면 방문자 이메일이 비어 있음 → UI는 "방문자로 실행" 배포가 필요 ④ 한 프로젝트에 설정이 다른 웹앱 배포를 둘 수 있음 ⑤ 개인 계정 쿼터(트리거 총 실행 90분/일, UrlFetch 2만 회/일, 실행당 6분) — 수치는 변동 가능, 배포 전 Google 문서로 재확인 |
→ 가정이 틀리면 구조의 해당 부분만 대체(§12). **S0 스파이크 전에는 R4(Telegram 처리)·R6(UI 인증)을 확정하지 않는다.**

## 1. 구조
```
GitHub Actions(radar) ─ 신호 알림 직후 서명된 POST ─▶ [API 배포] doPost  (신호 스냅샷 저장)
Telegram ◀─ 버튼 알림(진입했어/관망했어/놓쳤어)
Telegram ─ callback/메시지 ─▶ 수신(웹훅 or getUpdates 폴링)  ─▶ Sheets
사용자 폰 ─▶ [UI 배포] doGet(HtmlService 모바일 대시보드, Google 로그인) ─▶ Sheets
시간 트리거: 폴링(1분, 폴링 모드일 때) · 00:00 KST 일 마감 · 주간 백업
```
- **두 개의 웹앱 배포**: (1) *API 배포* — 나로 실행 / 누구나(익명): HMAC·비밀 경로로만 보호되는 `doPost`만 처리, `doGet`은 빈 응답. (2) *UI 배포* — **방문자로 실행** / Google 계정 필요: 이메일 허용 목록 검사 후 대시보드. Sheets는 소유자 계정 전용이므로 다른 사람은 열 수 없다.
- 코드는 저장소 `rich300/`에서 **순수 ESM 모듈**(`rich300/lib/*.mjs`)로 작성·Node 테스트하고, 빌드 스크립트가 GAS용 단일 파일(`dist/Code.gs`)로 묶는다(GAS 서비스는 얇은 어댑터 `gas/adapters.js`, 테스트는 가짜 서비스로). 배포는 사용자가 `clasp push` 또는 붙여넣기(Google 자격증명을 GitHub에 두지 않기 위함).
- radar 쪽 변경은 R9(마지막, 플래그 OFF, 가산적) 하나: 신호 알림에 `reply_markup`·`/ingest` 호출.

## 2. 데이터 구조 (Google Sheets, 시트=테이블, **추가 전용**)
금액은 **정수 마이크로 USDT**(1e-6)로 저장(시트 숫자는 배정밀도: 9×10¹⁵까지 정확). 시각은 UTC ms + KST 표시열.
| 시트 | 주요 열 | 규칙 |
|---|---|---|
| `Config` | key, value, rev, updatedAt | 시작 자금·시작일·목표율·시간대·마감 시각. 변경은 새 행(리비전) — 시작값·시작일 보존 |
| `Signals` | sid, strategy(A/B), symbolId, dir, signalAt, entry, stop, tp1, tp2, evidence, cfgVersion, snapshotHash | 불변. sid 유일. `symbolId`는 신호 알림 정보(공개 가능) |
| `Responses` | sid, choice(진입/관망/놓침), at, rev | sid당 1건 + 수정은 새 rev |
| `Fills` | fillId, sid, kind(진입/추가진입/부분청산/전량청산), at, price, qty, margin, leverage, plannedStop, feeState/fee, fundingState/funding, dirConfirmed, note, rev | 체결마다 1행. 유일키 `fillId` = `sid-순번-해시`. fee/funding 상태 = `entered`/`missing`/`estimated` |
| `Cashflows` | cfId, at, amount(+입금/−출금), note, rev | 손익과 분리 |
| `Equity` | date(KST), equity, realized, unrealized, source, at, rev | 사용자가 입력한 일별 **실제** 평가액 |
| `OpeningPositions` | symbol, dir, qty, startMark, origEntry | 시작 시점 미결제 포지션(기준가 재설정) |
| `Reviews` | sid, plan(4택), mind(4택), memo, savedAt, rev | **저장한 것만** 기록. 기본값은 저장 안 함 |
| `Adjustments` | adjId, at, amount, reason | 장부 차이를 사용자가 *이유와 함께* 명시 조정한 경우만 |
| `Audit` | seq, at, entity, key, op(create/revise/void), before, after, by, sheetHash | **불변 로그(진실의 원천)**. 다른 시트는 최신 리비전 뷰 |
| `TgUpdates` | updateId, callbackId, at | 재전송·중복 클릭 방지 |
| `Pairing` | codeHash, createdAt, usedAt | 1회용 페어링 |
- 삭제 없음: 취소는 `void` 리비전. 모든 수정은 `Audit`에 이전/이후 값을 남긴다. 사용자가 시트를 직접 고쳐도 `Audit`에서 재구성·불일치 감지(일 마감 시 무결성 점검).
- 쓰기는 `LockService`(스크립트 락)로 직렬화, 유일키 검사 후 추가 → 중복 기록 방지.
- 규모: 거래 하루 수 건 → 10년 치도 시트 한도(1,000만 셀)의 1% 미만.

## 3. 계산 규칙 (순수 모듈, 테스트 대상)
**복리 목표** — 당일 목표 마감 = 전일 *실제* 마감 × (1+g)(1일차 300→315). 미달분 강제 보전 없음. 별도로 이상선 300×(1+g)^n 고정(g 변경은 변경 시점부터 새 선분). 입출금은 일 손익에서 제외: 일 손익 = 마감 − 시작 − 순입출금. 달성률 = 오늘 손익 ÷ 오늘 목표 수익금. 목표 달성 여부는 신호·거래 규칙 어디에도 전달하지 않는다(radar로 역방향 경로 없음, 테스트로 고정).
**손익** — 평균 진입가는 체결 순서 가중평균(추가 진입 반영), LONG=(청산−평균)×수량, SHORT 반대. 수수료·펀딩은 입력/미입력/추정 3상태, 추정은 별도 열·배지, 미입력은 합계에서 제외하고 경고. 거래당 위험% = 증거금×레버리지×|진입−손절|/진입 ÷ 평가액(2% 초과·청산이 손절보다 가까우면 경고, 차단 아님).
**정합성** — 장부 잔고 = 시작 평가액 + Σ실현손익(수수료·펀딩 포함) + Σ순입출금 + Σ명시 조정. 입력 평가액과 차이를 항상 표시, 임계(0.5% 또는 1 USDT) 초과 시 "누락 거래·수수료·펀딩·입출금 확인" 카드. 자동 흡수 금지.
**시작 시 미결제 포지션** — 시작 평가액 = 지갑 잔고 + 시작 시점 미실현손익(입력). 기존 포지션은 `OpeningPositions`로 시작 마크가격을 기준가로 등록해 *시작 이후 변동분만* 챌린지 손익에 포함.
**일 마감** — 매일 00:00 KST(스크립트 시간대 Asia/Seoul): 장부 잔고 계산·`Equity` 입력 누락 표시(알림 발송은 승인 후, 기본 OFF).

## 4. Telegram 처리 방식 (모드는 S0 결과로 결정, 인터페이스는 동일)
| | 웹훅 | getUpdates 폴링(권장 기본안) |
|---|---|---|
| 반응 | 즉시(가정 ②가 맞으면 재전송 발생 → update_id 중복 제거 필수) | 1분 트리거, 최대 약 60초 지연 |
| 보호 | URL 비밀 쿼리(`?k=`)만 가능(헤더 불가) | 수신 서버 없음 — 외부에서 위조 요청 불가 |
| 쿼터 | 거의 없음 | 하루 1,440회 호출 + 트리거 실행시간(호출당 ≈0.5~1.5초 → 12~36분/일, 90분 한도 이내) |
- **버튼**: 신호 알림에 `진입했어/관망했어/놓쳤어`(`callback_data = "r1:{sid}:{e|w|m}"`, 64바이트 이내). 처리 순서: 발신자(`from.id`)가 페어링된 ID인지 → sid 존재 → `callback_query.id`/`update_id` 이미 처리? → 응답 저장(sid 유일) → 버튼 제거(키보드 수정) + 확인. 이미 응답한 sid는 "이미 기록됨(수정은 앱에서)".
- **입력 UX 정책(중요)**: 폴링 모드는 단계마다 최대 1분 대기라 *Telegram 대화형 5단계*가 느리다. 따라서 ① 3택 버튼과 복기 체크는 Telegram에서, ② 숫자 입력(증거금·레버리지·진입가·손절가, 청산가·수량·수수료·펀딩)은 **같은 sid로 열리는 모바일 입력 화면**(UI 배포의 prefilled 폼)에서 한 번에 받는 방식을 기본으로 하고, Telegram 텍스트 입력은 `/fill sid 증거금 레버리지 진입가 손절가` 한 줄 명령(+저장 확인 버튼)으로 지원한다. 웹훅이 S0에서 즉시 응답하면 대화형 마법사(상태기계, 10분 만료)도 켠다.
- **저장 정책**: 어떤 입력도 *확인(저장) 버튼*을 눌러야 기록. 복기 기본값(계획대로·침착)은 표시만, 저장 전 응답은 기록하지 않음.
- **허용 사용자 확인(하드코딩 금지)**: UI(Google 로그인 소유자)가 1회용 페어링 코드를 생성 → 사용자가 Telegram에서 봇에 `/pair 코드` 전송 → 스크립트가 코드 해시 검증 후 `from.id`를 **Script Properties**에 저장. 이후 해당 ID만 처리, 그 밖의 발신자는 무응답. 코드는 10분·1회용.

## 5. Actions → Apps Script 인증
- `doPost`는 헤더 불가이므로 **본문 서명**: `{"v":1,"ts":…,"nonce":…,"body":{…},"sig":"hex(HMAC-SHA256(key, v.ts.nonce.canonical(body)))"}`. GAS는 `Utilities.computeHmacSha256Signature`로 검증, `|now−ts| ≤ 5분`, `nonce`는 `CacheService`(10분)와 `Signals` sid 유일키로 재생 방지.
- 키 `RICH300_INGEST_KEY`: GitHub Actions Secret(발신)·GAS Script Properties(검증) 양쪽에 **사용자가 1회 등록**(채팅·로그·코드에 출력 금지). URL `RICH300_GAS_URL`도 Secret(공개 저장소에 배포 URL을 두지 않음).
- 호출은 `fetch(..., {redirect:'follow'})`(POST→302→결과 GET). 본문은 첫 요청에서 처리되므로 응답 확인 실패 시 **같은 sid로 재전송해도 중복 없음**(유일키). 실패해도 radar 알림에는 영향 없음(`catch`, 시간 제한, 플래그 OFF 기본).
- Actions 로그에는 sid 해시와 성공/실패만(종목·가격·본문 비출력).

## 7. 모바일 대시보드 (UI 배포, 한 열 레이아웃)
1. **오늘 카드**: 시작 잔고·오늘 목표 수익금·목표 마감 잔고·현재 평가액·오늘 실현손익·달성률(진행 막대).
2. **성장 그래프**: 실제 잔고 vs 300×(1+g)^n 이상선(선형/로그 토글, 인라인 SVG — 외부 의존성 없음), 입출금 마커, 최근 N일 범위.
3. **요약**: 누적 수익률(입출금 제외)·최고 평가액·최대 낙폭.
4. **정합성 배지**: 장부 vs 입력 차이, 임계 초과 시 확인 카드(누락 거래 후보 목록).
5. **위험 경고**: 거래당 위험%, 2% 초과·청산 근접.
6. 탭: **일지**(신호 카드: 전략·시각·가격 사다리·내 대응·실제 체결·이후 결과·복기) · **손익**(일/주/월) · **전략 A/B 실제 성적**(n<30 표본 부족) · **습관**(계획 준수율·심리별 손익·반복 실수·개선 행동 1~2개, 관찰이며 인과 아님) · **계좌**(평가액·입출금·시작 설정·OpeningPositions·조정) · **모의 성적**(별도 탭·별도 데이터 경로, 실제와 합산 함수 없음).
- 일일 5% 복리는 지속 불가(300→30일 1,297, 60일 5,604, 100일 약 39,450) — "도전 지표"로만 표시, 미달을 실패로 표현하지 않고 상시 위험 경고 배치.

## 8. 무료 운영 한계 (배포 전 Google 문서로 재확인)
- 비용 $0(개인 Google 계정). 쿼터 가정: 트리거 총 실행 90분/일, 실행당 6분, UrlFetch 2만 회/일, 동시 실행 30, 시간 트리거 최소 1분. 사용량: 폴링 1,440 호출·12~36분/일, 신호 수신·입력 하루 수십 회, 백업 주 1회 → 한도 내.
- 한도 위험: 폴링이 90분 한도에 근접하면 간격 2~5분으로 조정(적응형), Sheets 동시 쓰기는 락으로 직렬화, 응답 지연(콜드 스타트 1~3초).
- 서비스 정책 변경·계정 정지 위험 → 백업 필수.

## 9. 백업·수정 이력
- 주 1회(+ 대규모 변경 전) `DriveApp makeCopy`로 날짜별 사본(최근 8개 보관), Google 버전 기록 병행, 수동 내보내기(CSV/JSON) 버튼, 선택적으로 본인 Telegram으로 CSV 전송(승인 후).
- 배포 전 백업 → 마이그레이션은 `Config` 스키마 버전 + 롤백 사본.
- 수정 이력은 `Audit`(이전·이후 값·시각) — UI에서 항목별 이력 조회.

## 12. 위험·결정 사항
- **GAS 가정 5개 미검증**(§0): S0 결과에 따라 Telegram 수신 모드·UI 인증 방식 확정. 실패 시 대안: Cloudflare Worker(기존 계정·수동 배포 워크플로 재사용)로 수신/API만 교체하고 Sheets 대신 D1, 도메인 모듈은 그대로.
- 사용자 수동 작업 불가피: GAS 프로젝트 생성·배포(2개)·권한 승인, Script Properties에 토큰·키·허용 이메일 입력, GitHub Secret 2개 등록. 가이드와 체크리스트를 R8에 포함.
- 토큰이 GitHub와 GAS 두 곳에 존재(공격면 증가). 토큰 없이 처리하려면 웹훅 응답 방식이 필요한데 GAS는 302 응답이라 불가.
- 폴링 지연(최대 60초) — 입력 화면 중심 UX로 완화.
- 사용자 입력 의존(누락·오타) → 정합성 카드로 숨기지 않고 노출하되 완전 방지는 불가.
- 시트 직접 편집 가능 → `Audit` 불변 로그·무결성 점검으로 탐지(방지는 아님).
- 5% 일일 복리 목표 압박 → 레버리지 확대 위험(경고로 대응).
