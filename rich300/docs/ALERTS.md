# RICH300 보유 포지션 관리 알림 — 설계 (구현 전, 알림 비활성)

범위: 웹앱에 *사용자가 실제 체결했다고 등록한 포지션*만 감시한다. 추천 후보·미체결 감시 후보는 대상이 아니다. Binance 주문은 하지 않는다(자동 주문 없음).

## 1) 현재 상태 (코드 확인)
- RICH300(Apps Script)의 Telegram 송신: `/help` 응답, 신호 버튼 응답(진입/관망/놓침), 체결 초안 확인, 청산 뒤 복기 안내, 일 마감 알림(기본 OFF). 모든 송신은 `rich300TgGate_` 가 막는다(운영 승인 전 0건).
- **보유 포지션을 시간에 따라 감시해 먼저 알리는 기능은 없다.** `/plan`·`splanStatus` 는 사용자가 명령할 때만 상태를 계산한다.
- 감시 트리거: 없음. 존재하는 시간 트리거는 `rich300TgPoll`(1분, 수신 처리), `rich300CloseTick`(일 마감 + 매시간 재확인), `rich300BackupRun`(주 1회).

## 2) 입력 구분 (정확성)
| 구분 | 출처 | 신뢰 | 표시 |
|---|---|---|---|
| 실제 체결 | 사용자가 웹앱/텔레그램에 등록한 Fills | 기록 그대로 | "내 체결" |
| 시장 가격·봉 | 거래소 공개 시세(OKX 공개 API; 레이더가 이미 사용) | 지연 가능 | "시세 HH:MM 기준, N분 전" |
거래소 API 연동이 없으므로 체결·잔고가 자동 동기화된 것처럼 표시하지 않는다. 시세가 N분 이상 오래되면 판단을 만들지 않고 "시세 지연"만 알린다.

## 3) 상태와 규칙 (모두 수치 조건, 테스트 가능해야 함)
R = 진입 평균가와 현재 손절의 차이 × 남은 수량(=사전에 정한 위험 금액). 현재가·평균가·남은 수량·손절은 모두 기록에서 재계산한다.
| 알림 | 조건(초안) | 사용자가 할 행동 |
|---|---|---|
| 추가 진입 조건 충족 | 사전 지정 가격 도달 + 1h 추세 유지 + 거래량 확인 + 총 위험이 한도 이내 | "계획 2차 N USDT를 지정가에 직접 주문" |
| 추가 진입 취소 | 무효화 가격 이탈 또는 추세 반전 | "미체결 추가 주문 취소" |
| 손절 위험 | 현재가가 손절까지 남은 거리의 20% 이내 / 1h 종가 기준 구조 훼손 | "손절 주문 확인" |
| TP1/TP2 도달 | +1.5R / +2R | "50% / 30% 부분 청산 후 체결 등록" |
| 추적손절 변경 | 유리한 방향으로만 이동 | "손절을 X 로 올리기(내리기)" — 불리하게 넓히지 않음 |
| 스윙 전환 후보 | 수익 ≥ 설정 R, 4h 추세 유지, 거래량 지지, 구조 유지, 남은 포지션 손절이 진입가 이상 | "일부 청산 후 잔량 보유 여부 결정" |
| 스윙 유지/종료 후보 | 4h 추세·구조 유지 / 이탈 | 유지 또는 청산 검토 |
손실 포지션은 스윙 전환 후보가 될 수 없다(금지 규칙).

## 4) 중복·과다·오래된 신호 방지
상태 머신: 포지션별 `lastState`, `lastAlertAt`, `lastPriceAt` 을 저장하고 **상태가 바뀔 때만** 보낸다. 같은 상태 재알림 최소 간격(예: 60분), 시간당·일일 상한, 시세가 오래되면 송신 안 함, 포지션이 청산되면 모든 알림 종료. 전송 실패는 재시도 큐(최대 N회)이며 재시작 후에도 상태가 저장소에서 복구된다.

## 5) 구현 위치와 감시 주기 (제안)
- 판단: `rich300/lib/watch.mjs`(순수 함수: 포지션+봉 → 상태), 시세 수집은 Apps Script `UrlFetchApp`(OKX 공개, 키 없음) 또는 기존 레이더 상태 재사용.
- 트리거: 5분 시간 트리거 1개(`rich300WatchTick`), 보유 포지션이 없으면 즉시 종료(호출 0). Apps Script 일일 트리거 실행 시간 한도(무료 계정 90분/일)를 계측해 확인한다.
- 송신: 기존 게이트(`rich300TgGate_`)와 별도의 설정 `watchAlerts=off`(기본). 켜는 것은 사용자 승인 후.
- 테스트: 시세 가짜 데이터로 상태 전이·중복 방지·오래된 시세·실패 재시도·재시작 복구, 실제 Telegram 수신은 승인 후 1건씩.

이 문서는 설계이며 어떤 알림도 활성화하지 않는다. 위험 한도(1%/1.5%, 일일 -3%, 3배, 30%)는 4단계에서 반영한다.
