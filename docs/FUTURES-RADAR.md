# COIN RADAR 선물 레이더 (Phase 5 · Binance Futures OI & Funding)

화면의 **📈 선물** 탭에서 Binance USDⓈ-M 무기한 선물의 **미결제약정(OI)** 과 **Funding Rate** 를
현물 레이더의 **가격·거래 활동**과 함께 보여 줍니다.

> ⚠️ 모든 값은 **관측된 시장 데이터**입니다. "가격↑ · OI↑", "OI 급증", "선물시장 활동도" 등은
> 매수·매도·진입 방향을 제시하지 않으며, 상승·하락을 예측하지 않습니다. 투자 판단은 사용자에게 있습니다.

코드: `assets/futures-engine.js` (계산, 기준값 `FUT_RULES`), `index.html` (수집·화면)
테스트: `tests/futures-engine.test.js`, `tests/browser.test.mjs`

---

## 1. 왜 브라우저에서 직접 수집하나요

- Cloudflare Worker(서버)에서 Binance API 를 호출하면 **451/403 으로 차단**되는 것이 확인되었습니다
  (서울 Placement Hint 를 써도 동일, Phase 0 `/debug/reachability`).
- 사용자의 브라우저(한국)에서는 Binance 공개 API 가 정상 동작합니다.
- 그래서 선물 데이터는 **브라우저가 Binance 공식 공개 API 를 직접 호출**합니다. Worker 는 Binance 를 호출하지 않습니다.
- 프록시·비공식 미러·지역 우회는 사용하지 않습니다. API Key 도 필요 없습니다.

## 2. 데이터 출처 (Binance USDⓈ-M Futures 공식 공개 REST)

기본 주소: `https://fapi.binance.com`

| 용도 | Endpoint | 주기 |
|---|---|---|
| 선물 계약 목록 + Funding (전체) | `GET /fapi/v1/premiumIndex` | 처음 1회, 이후 1시간마다 |
| 종목별 Mark Price · 최근 Funding Rate · 다음 Funding 시각 | `GET /fapi/v1/premiumIndex?symbol=` | 1분마다 |
| 종목별 현재 미결제약정(계약 수량) | `GET /fapi/v1/openInterest?symbol=` | 1분마다 |
| 5분 단위 OI 이력 (처음 열었을 때 5분/15분/1시간 변화 계산용) | `GET /futures/data/openInterestHist?symbol=&period=5m&limit=13` | 이력이 1시간 미만일 때만 (종목당 10분에 최대 1회) |

- 요청은 동시에 4개씩만 보내며, 1분에 약 (종목 수 × 2)건입니다. (PC 15종목 ≈ 30건/분, 모바일 10종목 ≈ 20건/분)
- 화면이 1분 이상 숨겨지면 현물과 함께 수집을 멈춥니다.

### 감시 종목

1. 기본 6종목: BTC, ETH, SOL, XRP, DOGE, BNB
2. 현물 레이더가 자동 선정한 감시 종목(24H 거래대금 상위) 순서
3. 이 중 **실제 USDT 무기한 계약이 있는 종목만** 최대 **PC 15개 / 모바일 10개**
   - 분기물(`BTCUSDT_261226` 등), USDC 마진 계약은 제외
   - 선물 계약이 없는 종목은 "선물 없음: …" 으로 표시하고 계산하지 않습니다

## 3. Open Interest 계산

| 항목 | 계산 |
|---|---|
| 현재 OI 금액(USDT) | 현재 OI(계약 수량, `openInterest`) × Mark Price(`premiumIndex.markPrice`) |
| OI 변화율 5분 / 15분 / 1시간 | (최근 OI − n분 전 OI) ÷ n분 전 OI × 100, **계약 수량 기준** (가격 변동 영향 제외) |

- "n분 전 OI" 는 저장된 기록 중 n분 전 시각에서 **±2.5분 이내** 값만 사용합니다. 없으면 "수집 중" (추정하지 않음).
- 처음 열었을 때는 `openInterestHist`(5분 간격, Binance 제공 `sumOpenInterest`)로 1시간 이력을 채워 바로 계산합니다.
- 현재 OI 가 아직 없으면 이력의 Binance 제공 금액(`sumOpenInterestValue`)을 표시합니다.

### OI 상태 (15분 기준, 15분 값이 없으면 5분 기준)

| 구간 | OI 증가 / 감소 | OI 급증 / 급감 |
|---|---|---|
| 5분 | ±0.5% 이상 | ±1.5% 이상 |
| 15분 | ±1.0% 이상 | ±3.0% 이상 |
| 1시간 | ±2.0% 이상 | ±5.0% 이상 |

그 밖에는 "OI 변화 작음". 기준값: `FUT_RULES.oiThresholds`

## 4. Funding Rate

- `premiumIndex.lastFundingRate` (소수, 0.0001 = **0.01%**) 를 % 로 표시합니다. 다음 Funding 시각은 `nextFundingTime`.
- Funding 은 무기한 선물 가격을 현물 가격에 가깝게 유지하기 위해 일정 시각마다 포지션 보유자 간에 주고받는 비율입니다.

| 표시 | 조건 |
|---|---|
| 양수 펀딩 | Funding ≥ +0.005% |
| 중립 | \|Funding\| < 0.005% |
| 음수 펀딩 | Funding ≤ −0.005% |

기준값: `FUT_RULES.fundingNeutralPct`

---

## 5. 가격 + OI 조합

현물 레이더의 **15분 가격 변화**와 **15분 OI 변화**의 방향을 함께 표시합니다.

`가격↑ · OI↑` / `가격↑ · OI↓` / `가격↓ · OI↑` / `가격↓ · OI↓`
(변화가 ±0.1% 미만이면 `→`)

- 가격은 현물 레이더(Binance 현물 1분봉, `docs/RADAR.md`)의 15분 값입니다. 현물 15분 데이터가 없으면 조합을 표시하지 않습니다.
- 시장 포지션 변화를 **관찰하기 위한 표시**일 뿐, 어떤 매매 방향도 뜻하지 않습니다.

## 6. 선물시장 활동도 (Futures Activity, 0~100)

```
OI 점수(40)       = min(|15분 OI 변화| ÷ 3%, 1) × 40
가격 점수(20)     = min(|현물 15분 가격 변화| ÷ 2%, 1) × 20
거래 점수(20)     = min(max(현물 15분 거래 활동 배수 − 1, 0) ÷ 4, 1) × 20
Funding 점수(20)  = min(|Funding| ÷ 0.05%, 1) × 20
선물시장 활동도   = 합계 (반올림)
```

- 15분 OI 변화가 없으면 계산하지 않습니다 ("수집 중").
- 현물 가격·거래 활동, Funding 이 없으면 그 항목은 0점이고, 점수에 마우스를 올리면 "일부 데이터 수집 중" 으로 안내합니다.
- **점수가 높다 = 선물시장에서 강한/비정상적인 활동이 관측됨.** 상승/하락 예측이 아닙니다.
- 화면 정렬: 활동도 높은 순 → 같으면 기본 순서(BTC, ETH, SOL, XRP, DOGE, BNB, 이후 감시 순서). 점수가 없거나 지연된 종목은 뒤로.

예) 15분 OI +10%, 현물 15분 +3%, 거래 활동 2.0배, Funding +0.01%
→ 40 + 20 + 5 + 4 = **69**

기준값: `FUT_RULES.score`

## 7. 데이터 신선도와 장애 처리

| 상황 | 화면 |
|---|---|
| 정상 | `● 선물 정상` (초록), 카드마다 "갱신 시각 (n초 전)" |
| 종목의 마지막 갱신이 3분 초과 | 카드 흐리게 + `⚠️ 데이터 지연`, 활동도 `—` (정렬에서 뒤로) |
| 전체 수집 실패 (timeout 8초, HTTP 오류, 네트워크 오류, 오프라인) | `● 선물 재연결 중 (n초 후)` |
| 요청 제한 429 / IP 일시 차단 418 | 최소 **2분 / 5분** 기다린 뒤 재시도 |

- 재시도 간격(backoff): 5초 → 10초 → 20초 → … 최대 5분 (+무작위 1초 이내). 성공하면 다시 1분 주기.
- 인터넷이 다시 연결되면(online 이벤트) 바로 한 번 재시도합니다.
- 선물 오류는 **현물 레이더·Upbit 에 영향을 주지 않습니다** (상태 표시도 별도).

## 8. 브라우저 저장 (localStorage)

- 키: `coinradar.futures.v1` (현물 레이더 1분봉 `coinradar.candles.v1` 과 별도)
- 저장 항목: 시각, OI(계약 수량), OI 금액 — 모두 Binance 가 준 값 또는 그 곱
- 최근 **3시간**, 종목당 최대 **240개**만 보관, 감시 종목이 아닌 종목은 저장 시 제외
- `v`(스키마 버전)가 다르거나 형식이 깨진 데이터는 무시하고 새로 수집합니다 (사이트는 정상 동작)
