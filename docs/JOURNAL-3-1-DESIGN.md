# COIN RADAR 3.1 — 10초 매매 복기 기능 설계 (초안)

> **[갱신 2026-10-23] 저장·입력 방식은 `rich300/docs/DESIGN.md`(Google Apps Script + Sheets)로 대체되었다.** 이 문서의 *복기 질문·저장 규칙·실제 손익 계산 규칙·주간 분석 정의*는 그대로 유효하고 RICH 300 복기 기능이 이를 구현한다. §2 이하의 Artifact 기반 구조와 §6 PR 분할(J1~J6)은 참고용(대안 비교)으로만 남긴다.

> 기존 운영 시스템과 독립된 기능. 자동 주문·거래소 계정 연동 없음. 운영 배포와 실제 Telegram 연동은 별도 승인 후.
> 목표: 신호·모의매매는 AI가 자동 기록하고, 사용자는 청산 후 **체크 2개(+선택 메모) 저장**만 한다.

## 0. 저장소·저장 방식 점검 결과 (설계를 좌우하는 사실)
| 사실 | 영향 |
|---|---|
| 저장소 `j01044459979-prog/coin-radar`는 **public** | 이슈·데이터 브랜치·커밋·**Actions 로그는 전부 공개**. 실제 체결·손익·심리·메모는 여기에 둘 수 없다. 로그에도 출력 금지 |
| 운영 상태는 Actions 캐시(`radar-state-*`, 7일 미사용 시 삭제, 수십 KB 설계) | 장기 보관·불변 기록·개인 입력에 부적합 |
| Telegram 토큰은 GitHub Actions Secret에만 있음 | 서버가 없는 입력(버튼 콜백)은 radar 실행 주기(≈30분)에만 처리 가능 → 즉시 반응하는 화면은 불가 |
| `worker/`(Cloudflare Worker + D1, 서울 배치)는 Upbit 감시용으로 존재, Secret 없음 | 서버형 대안은 가능하나 새 Secret·웹훅·배포 승인이 필요 |
| 이슈 양식·`.github/ISSUE_TEMPLATE` 없음, 이미지 전송기는 `sendMessage`에 `reply_markup` 미지원 | URL 버튼은 추가 확장 필요(가산적 변경) |

**결론**: 자동 기록 대상(신호·모의매매)은 *시장 정보라 공개돼도 무방*하지만, 사용자 입력(실제 매매·복기)은 **비공개 저장소**에 둬야 한다.

## 1. 데이터 계층 분리
| 계층 | 내용 | 저장 위치 | 공개 가능 |
|---|---|---|---|
| S. 신호 스냅샷 | 신호 ID·전략·종목·방향·시각·진입/손절/TP1/TP2·근거·설정 버전 | 3.1 장부 v2(`state.ab`, 불변·해시 봉인) | 예 |
| P. 모의매매 | 가상 체결·TP/손절/만료·R·비용·펀딩 | 장부 v2 `origin: paper` | 예 |
| R. 실제 매매 | 진입함/패스/늦게, 체결가·수량·청산가·수수료·펀딩 | **비공개 Artifact DB** `real` | **아니오** |
| V. 복기 | 계획 준수·심리·메모, 저장 시각, 리비전 | **비공개 Artifact DB** `review` | **아니오** |
S·P와 R·V는 필드·저장소·집계가 완전히 분리되어 섞이지 않는다(합산 API 자체가 없다).

## 2. 권장 구조 (Phase 1: 새 서버·Secret 없음)
```
radar(Actions) ── 신호 알림 ──▶ Telegram  [🔗 복기] URL 버튼
                                   │  (URL 조각 #…에 신호 스냅샷, 서버 전송 없음)
                                   ▼
            복기 페이지(비공개 Artifact, 소유자 전용 DB)
            ├ 신호 카드(스냅샷)  ├ 체크 2개 + 메모 + 저장  ├ 실제 매매 입력  └ 주간 분석 탭
```
- **링크 조각(fragment)**: `#v1.{sid}.{전략}.{종목}.{방향}.{트리거시각}.{진입}.{손절}.{TP1}.{TP2}.{체크섬}` 형태의 짧은 문자열. 서버에 전송되지 않고(브라우저 안에서만), 체크섬으로 잘림·변조를 감지하며, 2048바이트 이하로 제한. 신호 ID가 DB 문서 ID라 **같은 신호의 중복 기록이 구조적으로 불가능**.
- **비공개성**: Artifact는 기본 비공개이고 입력 데이터는 소유자 전용 경로(`data/users/<id>/…`)에 저장. 이 기능은 공유 링크·공개 설정을 하지 않는다.
- **차트**: 신호 당시 이미지는 Telegram 대화에 이미 있다. 페이지는 스냅샷 가격 사다리(진입·손절·TP)만 그려 가볍게 유지(캔들을 URL에 싣지 않음).
- **복기 누락 여부**: 주간 Telegram 메시지(공개 가능 정보)에 지난 7일 신호 목록을 담은 링크 1개(`#w1…`)를 달면, 페이지가 가져와 비공개 DB에 신호 목록으로 저장하고 "복기 미저장" 신호를 표시한다.

### 대안 (참고)
- **B. Cloudflare Worker + D1**: 서버 측 결합(주간 Telegram 이미지에 복기 통계 포함), 링크 서명 검증 가능. 새 Secret(토큰)·웹훅·배포·GitHub↔Worker 키가 필요 → 별도 승인. Phase 1에서 수요가 확인되면 이전 가능하도록 스키마를 동일하게 유지.
- **C. GitHub 이슈 양식/데이터 브랜치 — 기각**: 공개 저장소라 개인 데이터 유출.
- **D. Telegram 인라인 버튼 콜백 — 기각**: 서버가 없어 radar 주기(≈30분)에만 처리 → 토글 UI가 지연됨.

## 3. 복기 UX (모바일 세로, 한 화면)
1. 상단: 신호 카드(전략명·종목·방향·시각·진입/손절/TP1/TP2, "모의매매 · 미검증 전략").
2. **내 행동**(3택): 진입함 / 패스 / 늦게 확인.
3. **Q1 계획 준수**: 계획대로 진입·청산 / 조기 청산 / 추격 진입·물타기 / 기타 위반. **Q2 심리**: 침착 / 불안·조급 / 손실 복구 욕심 / 욕심.
   - 기본 선택값은 **"계획대로 진입·청산", "침착"으로 *표시*만** 한다(회색 "저장 전" 표시). **저장 버튼을 눌러야만** `saved` 기록이 생기고, 저장 전 응답·페이지를 닫은 응답은 어디에도 기록되지 않는다(자동 저장·임시 저장 없음).
   - 진입함일 때만 Q1·Q2 필수. 패스·늦게 확인은 메모만 선택(계획 준수율·심리 집계에서 제외).
4. 선택 메모(최대 500자) · **저장**. 저장 후 수정 가능(리비전 추가, 이전 리비전 보존, 집계는 최신 리비전).
5. 실제 매매 입력(진입함일 때, 모두 선택): 실제 진입가·수량·청산가·진입/청산 수수료·펀딩. **빈칸은 "미입력"으로 남고 추정·기본값 채움 없음.**
6. 목록 화면: 최근 신호별 상태 배지 — `복기 저장`, `복기 누락`(진입함인데 미저장), `실제 체결 미확인`(손익 집계 제외).

## 4. 실제 손익 계산 (입력된 값만)
- LONG 총손익 = (청산가 − 진입가) × 수량, SHORT = (진입가 − 청산가) × 수량.
- 순손익 = 총손익 − 진입 수수료 − 청산 수수료 (**둘 다 명시 입력 필수**; 0이면 "0 입력" 체크). 펀딩이 미입력이면 `fundingIncluded:false`로 표시하고 순손익에는 넣지 않는다(추정 금지).
- 실제 R = 순손익 ÷ (|실제 진입가 − 신호 손절가| × 수량). 하나라도 없으면 `null` → **실제 손익 집계 제외**, "집계 제외 사유" 표시.
- 실제 체결이 확인되지 않은(진입가·수량 미입력) 거래는 모의 성적과 어떤 표에도 합산되지 않는다.
- 읽기 전용 거래소 연동은 이 설계에 없다. 필요하면 승인된 읽기 전용 키 방식(체결 내역 조회 전용, Secret 별도)을 별도 PR로 제안.

## 5. 주간 분석 (페이지의 "주간" 탭 — 비공개 데이터만으로 계산)
- 전략별 실제 성적(완료·순R·평균R·PF·최대 낙폭), **모의 성적은 Actions의 주간 성적표(별도 이미지)** — 두 표는 분리 표기.
- 계획 준수율 = "계획대로" ÷ 저장된 진입 복기 수(분모·표본 수 함께 표시).
- 심리별 평균 R·합계 R(그룹 표본 <5면 값 대신 "표본 부족").
- 반복 실수: 위반 유형별 건수와 손실 R 합계, 상위 2개.
- 개선 행동 1~2개: **규칙 기반 문장**(예: 조기 청산 ≥3건이고 평균 R이 계획대로보다 낮음 → "TP1 도달 전에는 청산하지 않기: 청산 전 체크"). 표본이 부족하면 "기록을 더 쌓으세요"만 표시. 모든 문장에 "관찰이며 원인 증명이 아님" 명시.
- 이 분석은 Telegram으로 보내지 않는다(비공개 유지). 주간 Telegram 성적표(Actions)에는 복기 데이터가 들어가지 않는다.

## 7. 위험과 대응
| 위험 | 대응 |
|---|---|
| 공개 저장소에 개인 데이터 유출 | 사용자 입력은 비공개 Artifact에만, 로그에 값 출력 금지(테스트로 로그 문자열 검사), 저장소·캐시에 R/V 계층 없음 |
