# 실시간 매매 판단 지원 신호 (진입 후보 알림)

> **자동 주문이 아니다.** 주문·계정 API는 어디에도 연결되어 있지 않다(공개 시세 GET과 Telegram 전송만 사용). 사람이 판단할 때 참고하는 알림이다.
> **이 규칙의 우위는 확인되지 않았다(미검증).** 상위 조건(기회 레이더)의 270일 백테스트와 15분 트리거를 더한 123일 백테스트 모두 평균 순손익비의 95% 신뢰구간이 0을 포함했다(`docs/OPPORTUNITY-BACKTEST.md`, `docs/SIGNAL-BACKTEST.md`).
> 기능 플래그 `RADAR_SIGNAL` 기본값은 **off**이며, 기회 레이더(`RADAR_OPPORTUNITY`)와 독립이다. 켜는 것은 별도 승인 사항이다.

## 1. 무엇을 하나

기회 레이더가 찾은 관찰 후보(4H 추세 + 1H 눌림 **2단계 이상**)에 대해서만, 15분봉이 마감될 때마다 **확정 봉**으로 진입 트리거를 점검한다.

| 상태 | 뜻 | Telegram |
|---|---|---|
| WAIT | 4H·1H 조건 미충족이거나 15분봉 데이터에 문제(부족·누락·미마감·지연) | 보내지 않음 |
| 관찰 | 4H·1H 구조는 갖췄고 15분봉 트리거(또는 거래량·손익비 등)를 기다리는 중 | 기회 레이더 2단계 알림이 이미 담당. 이 기능은 보내지 않음(미리보기·로그에는 막힌 이유를 표시) |
| **진입 후보** | 아래 조건을 **모두** 충족 | **전송** (신호당 1회) |
| **무효화** | 알린 진입 후보가 손절 기준 이탈·구조 소멸·방향 전환으로 더 이상 유효하지 않음 | **전송** (1회) |
| 만료 | 유효시간 경과 | 조용히 종료 |

### 진입 후보 조건 (LONG, SHORT는 대칭 — 별도 계산이 아니라 같은 규칙의 거울)
1. 4H 상승(하락) 추세 + 1H 지지(저항) 구간 눌림, 기회 레이더 **2단계 이상** (기존 단계 판정을 그대로 사용)
2. 15분봉 **확정 종가**가 직전 8개(2시간) 15분봉 고점(저점)을 돌파(이탈)하고 양봉(음봉)
3. 거래량: 트리거 봉 거래대금 ÷ 직전 20봉 평균 ≥ 1.2 (결측이면 불충족)
4. 구조: 최근 4시간 15분봉이 손절 기준을 건드리지 않았고, 가격이 구간 안쪽/위에 있음
5. 추격 아님: 구간 경계에서 1.0 ATR(1H) 이내, 트리거 봉 폭 ≤ 1.5 ATR(1H)
6. 손절 거리 1.0~3.5 ATR(1H)
7. **1차 목표가 계산 가능**하고, 비용 반영 손익비 ≥ 1.5R (`RADAR_SIGNAL_MIN_RR`)
8. 신호가 늦지 않음: 트리거 봉 마감 후 20분 이내

모든 임계값은 **제안값**이며 최적화·검증하지 않았다.

### 가격 계산 근거 (근거가 없으면 표시하지 않고 진입 후보로도 올리지 않음)
- **진입 관심가** = 트리거 15분봉의 확정 종가. 체결을 보장하지 않는 관찰 가격이다.
- **손절 기준** = 기존 분석의 구조적 무효화 가격 = min(눌림 12봉 최저가, 구간 하단) − 0.5 ATR(1H) (SHORT 대칭)
- **목표 1차** = 반대편 확정 구간(4H 스윙 고·저점, 최근 72시간 고·저점) 중 가장 가까운 것 중 1R 이상 떨어진 것
- **목표 2차** = 그다음 구간 중 1차보다 0.5R 이상 먼 것. 없으면 "산정 불가"로 표시
- **손익비** = 목표까지 거리 ÷ 손절까지 거리. **비용 반영 손익비** = 손익비 − 왕복 비용(수수료 0.10% + 슬리피지 0.05% = 0.15%)을 R로 환산한 값. 최소 기준 판단은 비용 반영 값으로 한다.
- 미완성 봉·미래 봉은 쓰지 않는다: 15분봉은 `confirm=1`만, 마지막 봉의 마감 시각이 현재 이하여야 한다.

### 유효시간·무효화·중복 방지
- 유효시간 = 트리거 봉 마감 시각 + 45분(`RADAR_SIGNAL_VALID_MIN`, 15~120). 메시지에 "생성 / 유효 ~까지"를 KST로 표시한다.
- 같은 (코인, 방향, 구간) 신호는 **한 번만** 알린다: 활성 중에는 새 트리거가 나와도 알리지 않고, 끝난 뒤에도 2시간(쿨다운) 동안 같은 구간·방향은 알리지 않는다. 같은 15분봉은 다시 처리하지 않는다.
- 무효화: 15분봉 **종가**가 손절 기준을 이탈, 4H·1H 구조 소멸(1단계 미만), 방향 전환, 1H 종가의 구조적 무효화 이탈. 꼬리(고저)만 닿은 것은 무효화가 아니다. 무효화는 알린 신호에 대해서만 1회 알린다.
- 하루(UTC) 진입 후보 알림 상한 20건(`RADAR_SIGNAL_MAX_PER_DAY`). 초과분은 보류한다(기록하지 않으므로 유효시간 안이면 다음 점검에서 다시 평가). 무효화 알림은 상한 대상이 아니다.
- 한 번에 여러 후보가 생기면 조건 적합도(기회 레이더 점수) 높은 순, 무효화가 먼저.

## 2. 안정성 계약 (기회 레이더와 동일)
- 상태는 `state.signal` 아래에만 쓴다. `state.opportunity`와 기존 정기 보고 상태는 **읽기만** 한다(관찰 후보 목록).
- 전송 전에 장부(`inflight`)를 저장한다. 장부를 저장할 수 없으면 보내지 않는다. 전달 여부가 불확실한 실패는 같은 메시지를 **최대 2회**까지만 시도하고 이후 전달된 것으로 간주한다. 명확한 HTTP 거절은 시도로 치지 않는다.
- 제한 시간(기본 90초, 프로세스 시간 예산 안): 지나면 새 요청·새 전송·새 상태 변경을 시작하지 않는다. 어떤 예외도 기존 레이더 실행에 번지지 않는다(`.catch(() => null)`).
- 거래소 제한 응답(403/418/429/451)은 즉시 중단하고 기존 정책(`waitMs`)만큼 쉰다. 기존 레이더가 대기 중이거나 상태 연속성이 의심되는 시간대(`quiet`)에는 같이 쉰다.
- 15분봉이 확정 대기·오래됨이면 신호를 만들지 않는다. 그래도 활성 신호의 시간 만료·1H 구조 소멸 판정은 계속한다.
- 호출 빈도: 기존 radar 실행(5분 슬롯) 뒤에 호출되고, 15분 슬롯마다 한 번(마감 20초 뒤부터) 평가한다. 관찰 후보가 없으면 네트워크 호출이 없다. 후보 N종목이면 호출은 약 3N+1회.
- **지연**: GitHub schedule은 수 분~수십 분 지연될 수 있다. 트리거 봉 마감 후 20분이 지나면 알리지 않는다(늦은 신호 방지).

## 3. 설정 (저장소 변수, 모두 기본값 안전)
| 변수 | 기본 | 의미 |
|---|---|---|
| `RADAR_SIGNAL` | `off` | `off` / `preview`(전송 없이 로그만) / `on` |
| `RADAR_SIGNAL_VALID_MIN` | `45` | 유효시간(분, 15~120) |
| `RADAR_SIGNAL_MIN_RR` | `1.5` | 1차 목표 비용 반영 최소 손익비(1~5) |
| `RADAR_SIGNAL_MAX_PER_DAY` | `20` | 하루 진입 후보 알림 상한(1~50) |
| `RADAR_SIGNAL_PAPER` | `off` | `on`이면 모의매매 성과 추적(전송 없음, `state.signal.paper`에만 기록). `RADAR_SIGNAL`이 preview·on일 때만 동작 |

범위를 벗어나거나 알 수 없는 값은 기본값으로 되돌린다(`RADAR_SIGNAL`은 `off`).
**신호는 기회 레이더가 저장한 관찰 후보를 쓰므로 `RADAR_OPPORTUNITY=on`일 때만 후보가 생긴다.** (`preview`에서는 기회 레이더 상태가 저장되지 않아 후보가 없다. 실데이터 미리보기는 아래 CLI/워크플로를 쓴다.)

읽기 전용 점검: `node radar-service/signal/preview-cli.mjs --top 20` 또는 `signal-preview` 워크플로(개발 브랜치 전용, 비밀값·상태 캐시 미사용).

## 4. 메시지
`docs/SIGNAL.md`의 예시는 테스트 합성 데이터로 만든 것이다. 실제 출력은 PR 보고 또는 `signal-preview` 실행 로그를 본다. 필수 표시: 종목·LONG/SHORT, 상태(관찰 ▶ 진입 후보 ▶ 무효화), 진입 관심가, 손절 기준, 목표 1·2차, 손익비(비용 반영), 근거 3개 이내, 생성 시각·유효시간, 위험(손절폭, 레버리지 시 증거금 손실 사실). 레버리지를 권하지 않는다.

### 이미지 알림 (진입 후보)
진입 후보는 **세로형 PNG 1장(1080×1560) + 2~3줄 캡션**으로 전송한다(`signal/chart.mjs`). 기존 차트 렌더러(resvg·Noto Sans KR 부분집합)와 `telegramPhotoSender`를 그대로 재사용한다.
- 내용: 종목·LONG(초록)/SHORT(빨강), 실제 확정 15분봉 56개 + 거래대금 패널, 진입 관심가·손절·1·2차 목표(가격선·손익 구간 음영), 비용 반영 손익비·손절폭·거래량 배율, 근거 3줄(4H 추세 / 1H 눌림목 / 15분 진입), 생성·유효시간, 무효화 조건, 미검증·주문 권고 아님.
- 가격은 `evaluateSignal` 결과와 수집한 확정 봉만 쓴다. 입력이 후보가 아니거나 봉이 부족·불일치·값 오류이면 이미지를 만들지 않는다(임의 값 생성 없음).
- **자동 전환**: 차트 생성 실패·15초 초과면 그 신호는 기존 텍스트 알림으로 보낸다. 사진이 HTTP 4xx로 거절되면 같은 시도에서 텍스트로 대체한다. 429·5xx·네트워크 오류는 기존 장부 규칙(최대 2회, 재시도는 텍스트)을 따른다. 무효화 알림은 항상 텍스트다.
- 판정·임계값·중복 방지·장부·모의매매 로직은 변경하지 않았다. `sendPhoto`가 없으면 이전과 완전히 같게 동작한다. 로그의 `SIGNAL {...}`에 `photoSent`·`photoFallback`·`chartFailed`가 있으면 표시된다.

## 5. 검증 상태 (그대로 읽을 것)
- **15분봉 트리거 포함 신호 규칙의 123일·19종목 백테스트 결과는 `docs/SIGNAL-BACKTEST.md`.** 신호 104건, 평균 순손익비 +0.21R(95% 신뢰구간 [−0.11, +0.53])로 **0과 구별되지 않았고**, 15분 트리거·거래량을 뺀 같은 맥락의 대조군(+0.04R, 1,398건)과도 구별되지 않았다. 후반 기간으로 갈수록 약해졌다(+0.35 → +0.06).
- 상위 조건(기회 레이더 2·3단계)의 270일 백테스트도 우위가 없었다(`docs/OPPORTUNITY-BACKTEST.md`).
- 따라서 이 신호는 **미검증 상태**이며 유리한 조건을 보장하지 않는다. 손익비는 구조적 목표 기준의 산식 값이지 도달 확률이 아니다. 스탑주문 기준 최대 역행폭이 평균 2.7%·p90 5.6%였으므로 레버리지가 높으면 손절 전에 청산될 수 있다.

## 6. 모의매매 성과 추적과 preview 절차
- 활성화 절차·합격/중단 기준·롤백·`on` 전환 체크리스트: **`docs/SIGNAL-PREVIEW-RUNBOOK.md`**.
- `RADAR_SIGNAL_PAPER=on`이면 진입 후보를 가상 거래로 기록하고 확정 15분봉으로 결과를 확정한다(규칙은 백테스트와 필드 단위로 동치). 로그 `SIGNAL-PAPER [모의·미검증] ...` 한 줄에 누적 성과가 나온다. 종료 30건 미만은 "표본 부족(결론 금지)", 이후에도 신뢰구간이 0을 넘을 때만 양/음으로 판정한다.

## 7. 주문 기능 없음
`signal/` 디렉터리에는 거래·계정·자산 API, 서명, 키, POST 요청이 없다(테스트 `주문·계정 API 흔적이 없다`가 소스를 검사한다).
