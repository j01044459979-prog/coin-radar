# COIN RADAR 단기 레이더 계산 방식 (Phase 2+3)

이 문서는 화면의 **"지금 움직이는 코인"** 이 어떻게 계산되는지 설명합니다.
계산 코드는 `assets/radar-engine.js` 에 있고, 기준 숫자는 파일 맨 위 `RULES` 에 모여 있습니다.
테스트는 `tests/radar-engine.test.js` 에 있습니다.

> ⚠️ 모든 상태 표시는 **데이터 상태**일 뿐이며 투자 권유가 아닙니다.
> 매수·매도 등 어떤 행동도 추천하지 않습니다.

## 1. 데이터 출처 (실제 Binance 데이터만)

| 용도 | Binance 공식 주소 | API Key |
|---|---|---|
| 실시간 1분봉 | WebSocket `<symbol>@kline_1m` (결합 스트림) | 필요 없음 |
| 실시간 가격·24H | WebSocket `<symbol>@ticker`(기본 6종목), `<symbol>@miniTicker`(나머지 감시 종목) | 필요 없음 |
| 과거 1분봉 보충 | REST `GET /api/v3/klines?interval=1m` | 필요 없음 |
| 감시 종목 선택 | REST `GET /api/v3/ticker/24hr` | 필요 없음 |

- 연결 주소: `wss://stream.binance.com:9443` (실패 시 공식 시세 전용 `wss://data-stream.binance.vision`),
  REST `https://api.binance.com` (실패 시 `https://data-api.binance.vision`).
- 모든 요청은 **사용자 브라우저에서 직접** 보냅니다. Cloudflare Worker 는 Binance 데이터를 중계하지 않습니다.
- 페이지를 열면 REST 로 최근 200개 1분봉을 받아 바로 계산을 시작하고, 이후에는 WebSocket 1분봉으로 이어 갑니다.
  연결이 끊겼다가 다시 연결되면 빠진 1분봉만 REST 로 보충합니다.

### 감시 종목 (universe)

- 24H 거래대금 상위 **PC 30개 / 모바일 20개** USDT 마켓 + 기본 6종목(BTC, ETH, SOL, XRP, DOGE, BNB).
- 스테이블코인(USDC, FDUSD 등)과 레버리지 토큰(…UP/…DOWN)은 제외합니다.
- 1시간마다 다시 선택합니다. 종목 수는 `index.html` 의 `UNIVERSE_SIZE` 로 바꿀 수 있습니다.

### 데이터 사용량 (대략)

- 전체 시장 스트림 대신 감시 종목만 받습니다.
- 화면이 1분 이상 숨겨지면(다른 앱으로 전환 등) 연결을 쉬고, 다시 보이면 재연결 + 빠진 1분봉만 보충합니다.

## 2. 1분 / 5분 / 15분 구간 계산

기준 시각은 **가장 최근에 완료된 1분봉**입니다. (진행 중인 1분봉은 거래량이 아직 다 쌓이지 않아 사용하지 않습니다.)

- **현재 구간(W분)** = 가장 최근 완료된 1분봉까지의 최근 W개 1분봉
- **가격 변화율(%)** = (구간 마지막 1분봉 종가 − 구간 첫 1분봉 시가) ÷ 구간 첫 1분봉 시가 × 100
- **거래대금** = 구간 1분봉들의 거래대금(USDT, Binance `q` 값) 합계
- **거래량** = 구간 1분봉들의 거래량(코인 수량, Binance `v` 값) 합계
- **방향** = 변화율 > 0 이면 상승, < 0 이면 하락, 0 이면 보합
- 화면 상단의 **현재가**는 실시간 ticker 값입니다.

예) 14:35:20 에 5분을 보면 → 14:30~14:35 (14:30, 31, 32, 33, 34 시작 1분봉 5개) 기준.

---

## 3. 평소 대비 거래 활동 배수

```
거래 활동 배수 = 현재 구간 거래대금 ÷ 평소 거래대금
평소 거래대금  = 현재 구간 바로 앞의 같은 길이 구간 최대 12개의 거래대금 평균
```

| 구간 | 평소(baseline)로 쓰는 범위 | 계산 시작에 필요한 최소 1분봉 |
|---|---|---|
| 1분 | 직전 1분 × 12개 (12분) | 1 × (1 + 6) = 7개 |
| 5분 | 직전 5분 × 12개 (60분) | 5 × (1 + 6) = 35개 |
| 15분 | 직전 15분 × 12개 (180분) | 15 × (1 + 6) = 105개 |

- 이전 구간이 **최소 6개** 없으면 계산하지 않고 **"W분 데이터 수집 중 (약 N분 남음)"** 으로 표시합니다.
- 1분봉이 중간에 빠져 있으면(끊김) 그 구간은 사용하지 않습니다. 빈 곳을 추정해서 채우지 않습니다.
- 마지막 완료 1분봉이 2분 넘게 들어오지 않으면 **"데이터 지연"** 으로 표시합니다.
- 평소 거래대금이 0 이면 배수를 계산하지 않고 "평소 거래 없음" 으로 표시합니다.

## 4. Radar score (0 ~ 100)

가격 변화와 거래 활동을 **반반** 반영합니다.

```
가격 점수(0~50) = min(|변화율| ÷ 급변 기준, 2) ÷ 2 × 50
거래 점수(0~50) = min(max(거래 활동 배수 − 1, 0), 4) ÷ 4 × 50
레이더 점수     = 가격 점수 + 거래 점수 (반올림)
```

- 급변 기준: **1분 ±0.5% · 5분 ±1.2% · 15분 ±2.0%**
- 가격 점수: 변화율이 급변 기준의 2배 이상이면 50점 (상승·하락 모두 같은 점수)
- 거래 점수: 평소와 같으면(1배) 0점, 5배 이상이면 50점
- 순위: 점수 높은 순 → 같으면 구간 거래대금 큰 순

예) 5분 +2.1%, 거래 활동 3.8배
→ 가격 점수 = min(2.1 ÷ 1.2, 2) ÷ 2 × 50 = 43.75
→ 거래 점수 = min(3.8 − 1, 4) ÷ 4 × 50 = 35
→ 레이더 점수 = 79

## 5. 상태 판정 기준 (데이터 상태)

| 상태 | 조건 |
|---|---|
| 과열 | \|변화율\| ≥ 급변 기준 × 2 **그리고** 거래 활동 ≥ 5배 |
| 가격 급변 | \|변화율\| ≥ 급변 기준 |
| 거래량 이상 | 거래 활동 ≥ 3배 |
| 활동 증가 | 거래 활동 ≥ 1.8배 (3배 미만) |
| 관찰 | 위 조건 없음 |

여러 조건이 동시에 맞으면 함께 표시합니다. 예) `가격 급변 + 거래량 이상`

화면에는 근거가 함께 나옵니다.

```
SOL  가격 급변 + 거래량 이상
5분 +2.10% (급변 기준 ±1.2%) · 거래대금 3.8배 (현재 $3.20M / 평소 $0.84M, 직전 12구간 평균)
```

## 6. 저장 (새로고침 대비)

- 브라우저 `localStorage` 키 `coinradar.candles.v1` 에 **완료된 1분봉만** 저장합니다.
- 저장 항목: 1분봉 시작 시각, 시가·고가·저가·종가, 거래량, 거래대금 (모두 Binance 가 준 값 그대로).
- 최근 **4시간**만 보관하고, 오래된 1분봉과 감시 종목이 아닌 종목은 자동 삭제합니다.
- 선택한 구간(1분/5분/15분)은 `coinradar.window` 에 저장합니다.
- 저장이 막힌 환경(사생활 보호 모드 등)에서도 화면은 정상 동작하며, 새로고침 시 REST 로 다시 받습니다.
