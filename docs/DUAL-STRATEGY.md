# COIN RADAR 듀얼 전략 3.0 (개발 브랜치 `feature/dual-strategy-3-0`)

> 목표: 추천 횟수보다 **위험조정 수익률**. 아래 모든 점수는 **조건 충족 점수이며 승률이 아니다.** 주문 실행 기능은 없다.
> 이 브랜치는 운영에 배포되지 않았다. 듀얼 평가는 기본 꺼짐이고, 기존 GitHub 스케줄·Telegram 운영(2.4)은 그대로다.

## 1. 현재 레이더 전략 감사 (코드 기준 사실)
| 항목 | 실제 구현 (`analysis.mjs` · `scoring.mjs` · `plan.mjs` · `enrich.mjs`) |
|---|---|
| 신호 | **5분봉** 직전 20봉 고(저)점 종가 돌파 + 단순평균(12봉 > 48봉) 추세 일치 + 마크가격이 레벨 바깥 |
| '강한 신호' | 위 + 거래대금 ≥ 2배 + 15분 OI ≥ +1% + \|펀딩\| ≤ 0.05% + 레벨 1 ATR 이내 + BTC 15분 변동 ±0.5% 역행 아님 |
| 점수(0~100) | 상위 시간대 정합 20 · 돌파 구조 20 · 거래대금 15 · OI 15 · 펀딩 10 · BTC 10 · 변동성/이격 10. 근접 후보 하한 40, 정기 추천 하한 55 |
| 계획 | 손절 = min(레벨−1 ATR, 12봉 스윙∓0.1 ATR), **TP1 = 1R(손익비 1:1)**, TP2 = 2R |
| 비용 | **수수료·슬리피지·펀딩 미반영**(코드 주석에도 명시) |
| 지표 | EMA200·RSI·MACD·Supertrend **없음** (단순평균·피벗·ATR만) |
| 검증 | **과거 성과 검증이 없었다.** 점수 가중치·임계값(40/55/75)은 경험칙이며 보정되지 않음 |
| 위험 | 5분 ATR 기반 손절은 가격의 0.3~0.6%대로 좁아 왕복 비용(≈0.2%)이 1R의 30~60%를 차지할 수 있음(백테스트 비용 표 참조). TP1 = 1R은 사용자 요구 최소 손익비 1:2에 미달 |
| 한계 | OI·펀딩 과거 이력을 길게 얻기 어려워 이 두 항목은 재현 백테스트 불가 → 기존 전략은 '가격·거래량 성분 근사'로만 비교 |

## 2. 전략 A — 트레이딩뷰에서 자주 쓰이는 지표 조합 (`dual/strategyA.mjs`)
- ⚠️ 이름의 의미는 "자주 쓰이는 지표"뿐이다. **트레이딩뷰 인기 순위·공식 전략·검증 수익률이 아니다.** 보고서에도 같은 문구를 표시한다.
- 1시간 확정봉. 설정값: Supertrend(ATR 10, 배수 3), EMA 200, RSI 14, MACD(12, 26, 9). 지표는 TradingView 정의(Wilder RMA, EMA 시드=SMA)를 따르며 RSI는 교과서 예제(70.46)와 일치함을 테스트.
- 점수: Supertrend 30(방향 + 전환 후 경과 봉 수로 신선도 감점) · EMA200 25(가격 위치 20 + 기울기 5) · MACD 25(히스토그램 방향 12 + 확대 8 + 0선 5) · RSI 20(50~68 만점, 과열·약세 감점).
- 계획: 손절 = Supertrend 라인(0.8~3 ATR 범위로 제한), 목표 = 2R.

## 3. 전략 B — 리치 자체 전략 (`dual/strategyB.mjs`)
- 1시간 확정봉. 가격 구조: 직전 20봉 고(저)점 **돌파 → 재테스트 지지(저항) 확인**(30점), 재테스트 전 즉시 돌파는 20점(가짜 돌파 위험).
- 상대 거래량(돌파 봉 거래대금/직전 20봉 평균) 15 · 유동성(24시간 거래대금) 10 · BTC 1시간 구조(종가·EMA50·EMA200) 정합 15 · 손절 거리/앞쪽 구조까지 여유(손익비) 20 · 추격/변동성 10.
- ATR 손절: 레벨/재테스트 극값 바깥 0.3 ATR, 목표 = **2R**(최소 손익비 1:2). 돌파 이전에 형성된 앞쪽 저항(지지)이 1.5R 안에 있으면 손익비 확보 어려움으로 **차단**.
- 제한(차단 사유): 급등·급락 추격(레벨에서 1.5 ATR 초과 이격) · 과도한 변동성(ATR 4%/시간 초과) · BTC와 반대 방향 · 유동성 부족(24시간 1M USDT 미만) · BTC 데이터 없음.

## 4. 결합 규칙 (`dual/combine.mjs`)
| 상황 | 판정 |
|---|---|
| A·B 같은 방향 + 각 75점 이상(B 차단 없음) + 시장 필터 통과 | **우선 추천 후보** |
| 방향 충돌(각 50점 이상) | **관망** |
| 한 전략만 75점 이상 / B 차단 있음 / 시장 필터 실패 | **관심 종목** |
| 그 외 | 신호 없음 |
- 시장 필터: BTC 데이터 부족 또는 BTC 1시간 ATR > 2.5% → 우선 후보 보류. **추천 0건 허용**, 후보를 채워 넣지 않는다.

## 5. 텔레그램 보고서 (`dual/report.mjs`, `RADAR_DUAL_REPORT=1`일 때만 사용)
종목 / 롱·숏·관망 / A 점수·근거 / B 점수·근거 / 진입 조건·손절·목표·손익비 / 위험 요인 / 무효화 조건 / 추천 시각·데이터 기준 시각. 우선 후보는 최대 2건 상세, 관심 종목은 한 줄씩. "점수는 승률이 아닌 조건 충족 점수", "정밀 평가한 종목 수"를 명시하고, 평가하지 않은 종목에 대해 신호를 확인했다고 말하지 않는다.

## 6. 추천 성과 추적 로그 (`dual/reclog.mjs`)
- 판정(우선/관심)이 나올 때마다 `{id, version, settings 해시, 신호 봉 시각, 데이터 기준 시각, 종목, 방향, 등급, A·B 점수, 진입 기준가·손절·목표·손익비, outcome}`을 남기고(`RECLOG` 실행 로그 한 줄 + `state.recLog` 최근 300건), 이후 실행에서 같은 체결 규칙(`simulateTrade`, 비용 포함)으로 손절/목표/기간 만료 결과를 채운다.
- `state.recLog`는 Actions 캐시 기반이라 영구 저장이 아니다. 장기 기록은 로그 수집 또는 별도 승인된 저장소가 필요하다.

## 7. 백테스트 방법 (`backtest/`)
- 데이터: OKX 공개 `history-candles` 1시간봉, 거래대금 상위 N종목 + BTC, 최대 365일. **현재 거래대금 상위로 고른 종목이라 생존 편향이 있다.**
- 미래 참조 방지: 모든 지표는 인과적으로 계산, 신호는 i봉 마감 후 0..i 데이터만 사용, 체결은 **i+1봉 시가**. 테스트로 "데이터를 잘라 계산한 i번째 값 = 전체로 계산한 값", "미래 봉을 바꿔도 과거 신호 불변"을 검증.
- 비용: 수수료 0.05%/편도 + 슬리피지 0.05%/편도 + 펀딩 0.01%/8h 가정을 R 단위로 환산해 차감(총손익과 나란히 표시).
- 체결: 손절·목표 동시 터치는 손절 우선, 시가 갭이 손절 밖이면 갭 가격 청산, 최대 보유 48봉, 종목당 동시 포지션 1개 + 쿨다운 6봉.
- 비교군: 기존(근사) TP1=1R / TP2=2R, A, B, A+B, 무작위 진입(같은 손절/목표 구조). 구간 분할 60/40(후반 40%를 기간 외 검증으로 별도 표시), 시장 구분(직전 30일 BTC 수익률 ±8%).
- 규칙·임계값(75점 등)은 **결과를 보기 전에 고정**했고 이 데이터로 조정하지 않았다. 임계값 민감도 표는 참고용이다.
- 지표: 승률, 평균 이익/손실, 기대값(R/거래), Profit Factor, 최대 낙폭(R), 기대값 95% 부트스트랩 구간, 표본·집중도 경고.

## 8. 사용법
- 개발 확인: `RADAR_DUAL=1 node radar-service/run.mjs --preview` (기능 브랜치 푸시는 자동으로 미리보기이며 전송 없음).
- 운영 전환(승인 후): 저장소 변수 `RADAR_DUAL=1`(계산·로그만) → `RADAR_DUAL_REPORT=1`(듀얼 보고로 교체). 기본은 둘 다 꺼짐. 끄면 즉시 기존 동작.
- 백테스트: `node radar-service/backtest/fetch-okx.mjs --days 365 --symbols 25 --out data.json.gz && node radar-service/backtest/run.mjs data.json.gz`.
